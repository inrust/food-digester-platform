# CMP 管理后台项目方反馈与开发规划

日期 2026-11-23 · 产品方案已确认 · 需求来源《当前问题20261123.docx》（9 页） · 代码基线 `main@92cda37b`

本轮共整理 **20 项改进**。优先修复离线设备显示正常、合约草稿创建后无法离开、停用账号无法启用、耗材备注被覆盖等问题。随后调整菜单和业务入口，再推进合约内录入客户、设备接入时录入站点、向上位机交付配置和接收耗材申请。

开发按确认后的产品行为执行。单项任务、依赖和可复制提示词见 [2026-11-23 开发顺序与提示词](CMP管理后台项目方反馈开发顺序与提示词-20261123.md)。

附件第 5 页提出为当前合约流程增加客户前置提示，第 6 页进一步要求在合约内录入客户。前者可用于兼容现有流程的过渡版本，正式交付按第 6 页办理。第 4 页要求恢复和删除停用站点，第 6 页要求取消独立站点管理。本计划把站点维护能力放在设备接入或设备管理上下文，独立入口在替代路径可用后下线。上一轮 44 项及其 T12 签收继续作为历史验收基线，本轮变更见下表。 [上一轮计划](CMP管理后台前端改进开发计划.md) · [T12 签收](CMP管理后台验收走查材料.md)

## 3. 实施要点

- **账号与设备状态。** 账号详情复用本人资料与已验证邮箱。账号启用延用 `user:write` 和现有 Cognito 意图及补偿机制，检查 Cognito 启用与业务状态同步、邀请未完成账号的恢复状态、重复与并发请求、启用审计。设备控制台沿用 DEC-024 的心跳判定（当前十分钟阈值）和服务生成时间，分开展示连接状态、最后一次上报和部件状态。用数据过期、无数据、断线与恢复场景验证，门限变化单独确认。 [Topbar](../apps/admin-web/src/shell/Topbar.tsx) · [账号服务](../apps/cloud-api/src/admin/user/service.ts) · [设备控制台](../apps/cloud-api/src/admin/device-console/service.ts)
- **对象子页面。** 复用现有媒体排序、授权状态机和设备用户页面。路由须携带可校验的设备或合约标识，前端切换对象时重置分页与过期响应。后端核验合约和设备关系、设备用户实际分配及租户范围。设备用户解除当前设备分配与全局停用账号的权限和影响分别呈现。旧路由无对象上下文时引导选择对象，有上下文时可安全解析到同一对象。告警证据及设备详情中的既有媒体直达链接一并回归。 [路由](../apps/admin-web/src/router/routes.ts) · [原型追踪矩阵](../contracts/prototype-traceability.yaml) · [合约与 License](dev/DEC-007-Contract与License关系.md)
- **合约与日期。** 使用日期输入控件和共享格式化逻辑。由服务端按第 4 节的业务日期边界统一映射至现有 UTC 时间戳及设备关联窗口。历史精确时间原样保存，未改日期的编辑提交保持原时间。现有草稿已可持久化，退出后从详情继续关联，继续沿用设备归属、关联排他及激活条件。客户内嵌录入复用 `customerId`，新客户与合约在同一业务事务提交。 [合约新建页](../apps/admin-web/src/pages/contracts/ContractNewPage.tsx) · [合约 API](dev/BE-CON-01-Contract-CRUD与状态API.md)
- **设备接入与站点。** 当前地域是 `Site` 属性，`Device.siteId` 为关系键，设备接入审批和设备分配已有各自的流程。由有首次设备分配权限的管理员在接入后的业务分配环节录入或选择站点，继续复用关系键与既有租户范围。指定重试、发证失败和旧设备无站点时的补录路径。站点恢复保留 `If-Match` 和审计，删除复用限关联设备的软删除，检查删除与分配并发时的约束。独立菜单下线前验证当前无关联、已停用及多设备共用站点都有可操作路径。[地域模型](dev/DEC-011-地域模型.md) · [站点服务](../apps/cloud-api/src/admin/site/service.ts) · [设备接入流程](设备无预置凭据Onboarding重设计方案.md) · [数据模型](../packages/database/prisma/schema.prisma)
- **配置 JSON。** 对照原型的 `image`、`operation`、`configuration`、`language`、`contract`、`alias`、`network` 与 DEC-018 当前四字段，逐项议定必填、默认值、单位、范围、派生来源及支持版本。优先验证复用 `CONFIG_CHANGED` → 设备 Sync 交付兼容 JSON。合约、地域和别名采用业务事实源。上位机支持可核验的版本回执时才能展示“已应用”。测试结构错误、离线补拉、不同设备目标、旧客户端和版本回退。 [管理后台原型](index19.html) · [配置版本 API](dev/BE-CFG-01-Configuration版本管理API.md) · [设备 Sync](dev/BE-SYNC-01-Unified-Device-Sync-API.md)
- **设备耗材工单。** 联调确定上位机或厨余机的上行入口、设备身份、申请标识、耗材类型、时间与重复/离线重传策略。管理端通过现有状态机处理 `PENDING → PROCESSING → COMPLETED`，同时验证取消路径，保留乐观锁和审计。以独立阶段字段或状态历史保存发起、处理、完成及取消备注。旧单据的可读字段原样兼容，可核实的历史备注按审计证据回填。界面将“处理”与“完成”的说明分别写清。设备入口联调通过后隐藏平台申请按钮，确认兼容窗口后限制旧创建 API。 [请求服务](../apps/cloud-api/src/consumable/request-service.ts) · [耗材契约](../contracts/rest/admin-consumable-request-api.json)
- **双角色交付。** 业务名称映射到现有 `PlatformSuperAdmin` 与 `PlatformOperator`。当前共享 RBAC 另有 `Auditor`、`CustomerAdmin`、`CustomerViewer`。开工先盘点 Cognito 组、业务角色表、邀请/分配、菜单、API、测试账号、客户隔离和审计。保留已有身份、组和审计能力。新平台账号及角色分配按第 4 节限制，服务端与前端采用同一口径。已有只读身份避免自动升权。 [原型角色映射](dev/DEC-012-原型角色映射.md) · [用户角色和 Scope API](BE-RBAC-01-用户角色与Scope管理API.md)

| 决策 | 执行口径 |

| 菜单与业务反馈 · R06、R18、R20 | 设备侧栏采用原型的“查看设备、操作设备、设备群管理、耗材查看”。告警与事件通过概览和设备详情访问。平台用户页移出业务设置和设备用户跳转，业务设置通过独立的受权限控制入口访问，保留耗材阈值、命令确认等既有能力。耗材处理和完成弹窗分别说明动作结果及本阶段备注要求。第 3、7、9 页的截图核对用于定位原控件，代码与原型的对应关系作为实施依据。 |

| 客户与站点 · R02、R09、R12、R16 | 沿用 `Customer → Site → Device`。合约内显式选择已有客户或录入新客户，客户与合约原子落库。由有首次分配权限的管理员在设备获批并进入可分配状态后，于 Onboarding 的业务分配步骤选择所属客户、录入或选择站点。只在同一客户范围内显式复用同名站点，停用站点先恢复再分配。设备管理与接入流程均可维护站点，覆盖无关联旧站点。 |
| 授权可达性 · R15 | 合约详情进入关联设备的授权。无适用合约的存量授权从对应设备详情进入，继续按现有权限和状态机管理。旧授权链接按已验证的合约或设备上下文导向相应入口。 |
| 配置与耗材协议 · R19、R20 | 配置优先沿用 `CONFIG_CHANGED` 通知与设备 Sync，向上位机交付带版本的 JSON。耗材采用设备认证的上行契约和可重试的申请标识。云端与设备方共同验证载荷、确认语义及旧版本兼容后再切换目标环境。应用状态来自可关联到设备与配置版本的回执。 |
| 两类平台角色 · R18 | “平台管理员”对应 `PlatformSuperAdmin`，“运维人员”对应 `PlatformOperator`。本轮收口平台账号管理中的新增邀请、分配候选和平台权限视图。存量审计及客户身份、客户侧已有管理入口、Cognito 组和服务端权限继续兼容。已有身份的处理沿用经授权的停用等操作，权限变更仍受服务端约束。 |

## 5. 验证与发布

1. **按编号回归。** 每个工作包提交时附 R 编号及测试结果。前端运行 `pnpm --filter @fdp/admin-web typecheck`、相关 `pnpm exec vitest run` 和 `pnpm check:admin-web-e2e`。API、数据或权限改动补充服务和契约回归，并执行 `pnpm openapi:check`。联合候选按仓库现行 `pnpm verify` 门禁验证。 [后台 E2E](dev/QA-05-管理后台E2E测试.md) · [原型回归](dev/QA-08-客户原型追踪与视觉行为回归测试.md)
2. **验证存量与异常。** 覆盖未验证邮箱、停用账号、旧草稿、无站点设备、停用站点、旧书签、跨设备与跨租户、离线设备、旧配置版本和旧耗材单据。对写入操作验证校验失败、刷新读回、重复请求、并发与审计，使用两种界面语言走查关键路径。
3. **分批切换。** 先发布兼容 API 与数据迁移，再切前端入口。新工作流分别完成设备接入、上位机配置与耗材申请实测后，再移除旧入口或限制旧写路径。发生回归时按工作包回退入口或协议版本，保留已产生的业务及审计数据。
4. **登记现场证据。** 对 R01–R20 记录角色、测试数据、操作步骤、预期和实际结果、候选版本及脱敏证据。对截图指代未核实项标 `OPEN`，尚未执行的实现与环境验收标 `NOT_RUN`。本文件为开发规划，代码调查采用本地静态基线。
