## 条目模型

每条决策（DEC-xxx）包含：`id`、`version`（semver，frozen 必须 >= 1.0.0）、`status`（pending/proposed/frozen/superseded）、`title`、`conflict`、`provisionalValue`、`approver`、`approvedAt`、`blockingTasks`、`affectedModules`、`sourceRefs`、`history`。

状态不变量由自动检查强制：

- `pending`/`proposed`：`approver`、`approvedAt` 必须为 `null`；
- `frozen`：必须有批准人、UTC 批准时间，版本 >= 1.0.0；
- 条目版本必须等于 `history` 末条版本；任何修改必须追加 history 并提升 `registerVersion`。

## 决策版本引用约定

契约包和 OpenAPI 构建通过以下字段引用决策版本：

- MQTT JSON Schema / Topic Catalog：在 Schema 顶层声明 `"x-decision-versions": ["DEC-002@1.0.0", "ADP-002@1.0.0"]`；
- OpenAPI：声明 `info.x-decision-versions`（格式同上，`决策ID@版本`）；
- 契约包整体：`contracts/contract-version.json` 的 `decisionRegisterVersion` 必须等于登记的 `registerVersion`。

## 自动检查

```bash
# 结构校验 + 未决决策报告（退出码 0=通过，1=结构失败）
node scripts/check-decisions.mjs

# 门禁模式：存在未决决策时退出码 2（供 ENG-02 质量门禁与契约发布使用）
node scripts/check-decisions.mjs --fail-on-pending

# 机器可读输出
node scripts/check-decisions.mjs --json

# 追溯校验：契约文件的 x-decision-versions 引用必须存在且版本一致
node scripts/check-decisions.mjs trace <schema-or-openapi.json> [...]

# 测试
node --test "scripts/*.test.mjs"
```

检查覆盖验收基准：

1. **识别未决决策**：validate 模式列出全部 pending/proposed 决策及其阻塞任务；
2. **唯一决策 ID**：DEC/PRI/ADP 全登记唯一，重复即失败；
3. **Schema 可追溯到决策版本**：trace 模式校验每个 `x-decision-versions` 引用存在且版本与登记一致。

## 变更流程

1. 复制 [decision-change-template.md](../../contracts/decisions/decision-change-template.md) 填写变更；
2. 修改 `decision-register.json`：更新条目、追加 history、提升 `registerVersion`、更新 `updatedAt`（UTC）；
3. 同步更新 `contract-version.json` 的 `decisionRegisterVersion` 及受影响契约文件的 `x-decision-versions`；
4. 运行上述检查与测试，全部通过后提交。
