使用 Node 24.12、本机已登录 esgiot-infra/esgiot-readonly SSO、真实 Chromium。先等人工推送的提交完成 CI、Deploy test API 和 Amplify；重新读取 Lambda 工件并绑定版本回执。

```sh

node --import tsx scripts/run-qa09-business-target.mjs <target.json> <version.json>
```

version 的历史工件复用输入只能来自先前真实 PASS 回执；每次重读 CodeSha256、CloudFormation 位置和部署信息，未验证版本不得执行业务写入。`run-qa09-business-target` 先启动十设备 CSR/mTLS/MQTT 正向/负向基线，再调用业务扩展；原十设备执行器不指定扩展时保留原功能。

扩展通过真实 Cognito SRP 准备其余四角色，CustomerAdmin/Viewer 绑定 Customer A；浏览器五角色均使用实际用户名/密码经已部署登录页登录，不改 JWT payload、角色或 scope，不拦截 API、不启动本机 API。浏览器关闭 HAR、Trace、录像与持久凭据，截图只保留像素摘要，不输出 Cookie/Authorization、Token、密码或私钥。

长时执行在 API 会话即将到期时重新使用本轮身份进行真实 SRP，不改密码；清理前续登录并同步原十设备执行器的 SuperAdmin 会话。新增身份/站点/导出创建ID即时归档，密码与续登录结果仍只在内存。浏览器等待实际 dashboard 加载及路由网络请求完成；桌面路由矩阵与 dashboard 1440/375px 布局是已实现范围，不等于全页面移动行为/原型语义快照比较。

核心业务覆盖合同生命周期及同版本并发、合同设备关联、License、Configuration、Device User、耗材、报警及多领域读取矩阵。安全阶段覆盖匿名拒绝、非法/未知 body、邀请 password 拒绝、业务副作用计数不变、审计原文的凭据模式扫描。故障恢复针对本轮 API 创建的 ESG 导出，精确 ID + Customer + Device filters 条件修改为已过期 PROCESSING 租约，观察真实定时 Worker 恢复，核验 CSV 行数。

HTTP 负载为 10 并发、计划300次本轮设备读取；每批所有请求结束后再判断失败，失败不会跳过独立MQTT阶段。真实 MQTT quick 配置计划执行正常 120 秒、历史窗口共 480 秒、30 倍突发 10 秒，900 个唯一 Telemetry、20 个 Heartbeat、5% 重复和 2% 乱序，另加基线 20 Telemetry/10 Heartbeat。历史覆盖 24 个小时，每小时仅 quick 窗口；最旧补报使用 24 小时边界内 5 秒余量。它不等同 full 配置的全天逐样本补报，也不等同墙钟等待 24 小时。

归档校验使用既有 Replay role 在 AWS 内比较本轮发布 payload 规范化摘要、Outbox 原文摘要及 gzip 原文；quick 模式严格要求 950 条唯一消息账本、920 条 Telemetry，且保持对象和解压大小上限，不允许用 profile 切换跳过缺失归档。只输出元数据，无新 IAM 策略。

## 清理与漂移防护

所有身份、Customer、Site、设备均由随机前缀和创建账本限定。数据库扩展仅接受精确十设备/双 Customer；业务基线哈希覆盖本轮 scope 之外的合同、License、配置、设备用户等表。漂移时拒绝删除；依赖记录先于父记录删除；审计与软删除 Customer/Site 历史保留。共享设置和其他客户对象不修改。

新增 Device User/License/Contract/Configuration/耗材/导出及设备关联清理完成后，以独立只读 business-audit 验证零业务残留和原摘要；清理自己的 Site，撤销四身份，然后原执行器清理证书/库存/请求、原始归档版本、双 Customer 和 SuperAdmin。quick 模式使用精确双 Customer 的 raw heartbeat/telemetry 前缀批量删版本并再次列出证明为空，避免千条对象逐项清理拖延。

专用夹具 CodeBuild 仍单并发，各 seed/observe/cleanup/audit 严格串行。业务扩展或云端探针失败时继续执行其他独立阶段与清理；没有完成时间和清理证明时 Gate 失败关闭。

## Gate 边界

定向core执行器创建真实RDS Onboarded库存状态，再经API分配设备并执行生命周期；`fixtureMode=REAL_RDS_ONBOARDED_STATE_FOR_BUSINESS_APIS_NO_DEVICE_AUTH_CLAIM`，不生成/模拟证书或IoT消息。其身份仍经真实Cognito SRP登录；成功后对业务表零残留、范围外摘要、设备库存、客户、身份、License归档分别清理与校验。不能用这轮替代已有十设备设备认证证据。

CloudWatch大JSON可能拆分为多个日志事件，桥接器在大小上限内重组单个结构化帧，并拒绝截断/多帧/非相邻污染；仍校验Build ID、指定角色/VPC、执行源码摘要、action与前缀。历史失败回执保留，独立恢复结果另存。

MQTT发布使用受限并行（最多64在途），逐条即时保存NDJSON发布尝试与PUBACK元数据和摘要，失败也能追溯发布端；不保存raw payload或认证信息。burst断言比较实际300条唯一消息生成跨度≤11秒，并在Gate与真实DB已处理行相互绑定，计划标签不构成速率证明。当前环境旧实跑burst为160.57秒，仍FAIL。DB processed延迟不等于API可见SLO。

完整驱动器按子回执和清理Gate设置非零退出码，避免父设备流程成功掩盖业务失败；完成后只对双Customer License DOMAIN归档精确前缀删版本并复核为空。汇总器逐项重验真实来源、数据库Build、业务摘要、恢复清理和五角色证据；完整QA仍PARTIAL时退出2，不能当作完整PASS。

Device User跨客户分配契约是409 CONFLICT；拒绝后再读取详情，验证version和完整分配历史均不变。定向core复验继续覆盖五角色设备租户矩阵，其18×5领域读取的完整证明来自同一已部署版本的前轮不可变回执，汇总时逐条验真。

POST连接超时不能假设未产生对象。`audit-unseeded-prefix`固定只读查询该前缀两个客户名和十设备ID，不接受任意SQL或已有客户ID；确认副作用后再处理，禁止盲目创建重试。新身份删除辅助程序还绑定原创建时间和邮箱，使用AdminDelete而非密码重置；客户端globalSignOut失败不阻止资源删除尝试，退出结果单独保留，不能伪造成功撤销所有历史JWT。


已完成Build结果缺失时，先 `recover-qa09-db-result.mjs <original.json> <recovered.json>` 只读恢复；不重跑SQL。核心断言和清理验真分开：`validateTargetAssertions`只有assertionsGate，没有整体验收gate；必须经 `check-qa09-core-recovered-target.mjs` 将原始断言、冻结源码、原正常数据库清理、只读业务审计和独立Site/客户/身份/归档清理绑定后，才允许恢复后的核心子Gate PASS。原FAIL及cleanupComplete=false始终保留。恢复动作只接受已完成账本与精确创建ID。

CloudWatch结果读取最多15次、45秒预算，对空/截断和临时读取错误仅重复读取；错误源码/前缀/多个帧/FAIL/AccessDenied立即拒绝。客户端读取失败会留下结束时间和失败代码，不再停留于误导性的RUNNING。

核心PASS仅代表已列业务子范围，完整QA-04仍需Suspend/Reactivate/Retire/Command及更新后Sync，全写API五角色矩阵仍待补；共享Worker暂停未授权，专用队列重投已授权但尚未执行。实际汇总仍PARTIAL、退出2。
