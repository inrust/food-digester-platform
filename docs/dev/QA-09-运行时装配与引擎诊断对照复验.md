## 阶段定义

`runtime-client-construct`围绕同步createPrismaClient；`runtime-route-assembly`围绕现有全部端口、handler与router装配。两阶段均在相同runtime-initialize内，两个Secret成功后、认证/账号hook前，按先后执行；不会调用$connect/checkout/SQL。Secret解析失败不会创建client，client构造失败不会进入装配，warm和单飞并发初始化不重复装配。原错误/单飞重试保持。

两阶段在engine诊断on/off都输出wall、非负整数processCpuUserUs/processCpuSystemUs和PROCESS_ALL_THREADS；进程全部线程区间含后台工作，不能认定纯构造CPU，也不相加当应用总量。新--runtime-assembly验证五个初始化阶段唯一、成功、精确ID、嵌套/先后及CPU；warm无初始化阶段返回null，不能填0。原失败初始化仍独立FAIL证据，不作为成功业务阶段验收。结合唯一本请求REPORT才能宣称物理冷，不用client ready替代。

新分析器输出client构造、装配及最后Secret后的未分段时间区间；按startedAt/completedAt计算窗口，durationMs独立时钟和取整可能有差异，不抹除差异或拼接嵌套CPU。

## 可重现部署输入

测试工作流新增workflow_dispatch输入：

- expected_commit：当前main的完整40位SHA，必须等于GITHUB_SHA和实际checkout HEAD。
- engine_cpu_diagnosis：显式字符串false或true；false覆盖仓库变量true，不使用真假值fallback选择手动输入。
- rollout_phase：capacity或immediate，必须与仓库当前FDP_QA09_ROLLOUT_PHASE一致；本环境应保持既有immediate，不能为了对照回退Command发布或改变预算。

只允许main，FDP_DEPLOY_ENABLED原开关仍生效；push沿用原变量/默认值。resolve脚本在verify/AWS凭据/部署之前验证输入，并以GITHUB_ENV写入枚举；手动值仅进入env，未拼接shell命令。错误SHA/branch/phase/mode在云端动作前失败。full verify失败也不会部署。

每次生成`qa09-deployment-inputs.json`，上传artifact `qa09-deployment-inputs-<runId>-<attempt>`（30天）；含source SHA、run/attempt、event、有效rollout/engine/context、workflow/resolver/config指纹，不记录角色/证书引用原值或凭据。config指纹包含现有部署配置与关键证书/truststore/部署角色引用；不能证明外部资源未漂移。回执只证明输入，不能证明部署成功、19字节、实际flag、业务或P95。

人工GitHub Desktop推送本轮提交后，在main保持同SHA且未再推送的情况下，依次手动dispatch off、on；保留现有共享部署concurrency group、不取消运行。不要在同一时间启动两组业务夹具；每单元部署成功后完成全部版本、业务及清理，再开始下一单元。若main在两个dispatch间变更，第二单元输入验证应失败，重新规划新SHA而非混合结果。工作流首次push的默认部署不自动计为手动off/on单元。

GitHub手动输入行为参考[官方文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)；实施记录当时未实际dispatch；后续目标复验已顺序dispatch off37555699502/on37563191928，未更改GitHub变量。

## 每单元操作与门禁

下载对应run/attempt的回执到各自证据目录，先绑定实际GitHub run/headSHA/成功结论（包括verify步骤）与下载artifact；不能仅信任可手写JSON。沿用版本collector，QA09_EXPECTED_COMMIT设本轮完整SHA、QA09_DEPLOY_RUN_ID设各自deploy run ID，核对CI/Deploy/Amplify及19实际ZIP。读回API有效环境和容量（只查询安全字段，不输出完整ENV）：ENV_NAME=test、pool1、512MiB、reserved12，engine旗标必须匹配回执；Secret默认并行绑定新SHA实际源码。

输入pair检查（命令参数严格三文件）：

```sh
node scripts/record-qa09-deployment-inputs.mjs --pair <off-inputs.json> <on-inputs.json> <input-pair.json>
```

要求不同手动run、同SHA/phase/workflow/resolver/config指纹、正确false/true及派生context。输出scope=INPUT_COMPARABILITY_ONLY、targetVersionGate/业务NOT_EVALUATED，不能改成验收PASS；原下载回执和文件哈希保存。19工件/实际配置配对另证，API revision因受控flag更新可不同，代码实际字节与预算必须独立验证。
