# QA-09 运营最小材料清单

依据 2026-10-13 用户指令：取消新建验签/签名通道和 IAM 角色的要求，优先使用现有设备、获权服务和现成签名包。运营只提供材料或说明材料不可得，不要求调整 IAM/KMS 权限。

| 需要提供 | 最少内容 | 取得方式 |
| --- | --- | --- |
| 真实许可证独立验签回执 | 设备/客户、许可证 ID/版本、验签时间与成功/失败；绑定当前 Sync 的 ETag、nonce、证书指纹、许可证有效期和功能权限；原文与签名摘要、验签程序/密钥版本标识 | 已配好密钥的测试设备或已有获权服务内部验签。研发准备当轮输入；设备/服务保管密钥，只返回回执 |
| 一个被测试环境信任的签名测试包 | 文件；model、version、packageType、文件 SHA256；对应公开签名、签名算法和测试信任根标识/公钥 | 优先提供现成合法包；否则使用已有获权签名服务。可使用研发准备的非可刷写云端协议夹具，不要求量产固件 |

研发负责准备当前输入和生成收据字段，运营无需手工填写全部字段；也可先提供已有测试设备或获权服务的标识，由研发对接现有能力。

无需提供密钥值、私钥、SecretString、访问令牌、完整权限策略或管理员权限。无需创建角色、CodeBuild 项目或常驻服务。

如已有获权渠道无法取得某项材料，回复“许可证验签材料未提供”或“可信签名包未提供”，并给出原因即可；不要为此申请或扩大权限。该项及依赖它的成功业务路径记录为未验收/发布前必验，不记 PASS。

研发会核验材料的版本、设备和文件绑定，保留真实许可证验签及可信包验签，然后完成实际云端业务。仅发送 VERIFIED 状态、拿本地自造密钥验签、只测试坏包拒绝，都不能代替这些证明。

本地待签名文件位于 `build/qa09-private-a2-20261013/`：`unsigned-firmware-fixture.bin`、`firmware-signing-payload.txt`、`firmware-sign-request.json`。完整原始材料留本地；公开仓库只保存代码和脱敏摘要。旧的新增角色/权限提案已退出执行计划，不应据旧提案操作。
