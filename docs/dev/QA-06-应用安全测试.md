# QA-06 应用安全测试

依据 [开发任务清单](../管理后台开发任务清单.md#qa-06-建立应用安全测试)。套件复用 AUTH-01～04、SEC-01、设备接口与管理写 API 的安全回归，新增实际签名 JWT→生产 Lambda 认证→真实 Handler/PGlite 的跨层探针，以及独立的敏感产物扫描器。

## 执行

```sh
pnpm test:security-suite /tmp/qa06-local-security.json
node --import tsx --test scripts/security-suite.test.mjs
pnpm verify
```

需要仓库锁定依赖与已生成 Prisma Client；安全套件本身不需要网络、AWS 凭据或浏览器。完整 `verify` 另包含 QA-05 的 localhost Chromium 测试。专用 runner 使用 `qa06-vitest.config.mjs` 固定运行 20 文件/202 测试；普通 Vitest 也自动包含新增测试。

## 覆盖与身份语义

| 范围 | 可执行验证 |
| --- | --- |
| JWT 完整性与时间 | 本地随机 RS256/JWKS 验签；伪造/改角色、issuer/client 不符、缺 exp、过期、畸形或超前 auth_time 均拒绝 |
| 管理写接口身份边界 | 生产 DELIVERED_OPERATIONS 中全部 63 个管理写接口 × 缺凭据/过期/伪造 JWT = 189 次 401；伪 actor/authorizer claims 不能进入路由解析 |
| 重放 | CSR 签名轮询 nonce 重用拒绝；OTA grant 绑定 device/target/package/expiry/unused/revoked 且只消费一次 |
| Customer 与角色 | 真签名 Customer JWT scope 不被 query、actor、authorizer 伪造覆盖；跨 Customer 403，拒绝写操作无业务/审计变化；复用用户、角色、命令、设置等服务端负测试 |
| Topic 越权 | 生产 IoT Policy 生成器的本地字面量求值：跨设备 Client ID/Topic、通配和错误方向拒绝 |
| mTLS 白名单 | 真实迁移/数据库登记、未登记/撤销/过期/未生效、跨设备及 Retired 例外；Device Lambda 不信任 body/header 伪身份 |
| SQL/JSON 注入 | 七类畸形/类型/未知字段/原型污染输入返回 400，不写业务或污染 Object.prototype；SQL 片段按普通名称字面量存储，不执行 SQL，不扩大查询 scope |
| 恶意文件元数据 | 12 类路径、URL、空字符、脚本、超长名称、伪 Key/Bucket、大小/Hash 等攻击；全部 400，签发 URL/会话/对象/审计均为0 |
| URL 范围 | Media 上传 Key 与会话精确绑定，跨设备/任意 Key 拒绝；管理下载跨 Customer/删除对象拒绝；过期/撤销/已消费 OTA grant 不签 URL |
| 敏感产物 | Token/privateKey/passwordHash 合成 canary 检查响应、四级 Logger、Trace JSON 快照及落库审计；另扫描原始 stdout/stderr、Vitest JSON、trace 与现有 .snap 文件 |

有效 Bearer JWT 在有效期内复用是正常认证行为，不是一次性 nonce。本套件验证非法/过期/篡改 Token 重用不能授权，以及业务一次性凭证重放被拒绝；未新增全局 JWT jti 黑名单，也不把 Cognito 全局退出/吊销后的真实拒绝时点视为已验证。Onboarding 的首次申请是公开 CSR 入口，不能要求所有公开请求返回 401；设备写接口走 mTLS，均由其既有正负测试验证。

Topic 求值证明的是生产 Policy 的静态允许/拒绝语义；证书测试证明数据库白名单与可信 Gateway context 接线，部分证书为确定性 PEM 指纹夹具，不是实际 AWS TLS 握手证据。

## 隔离、产物与 Gate

- 新增数据库场景各自随机 `QA06-<12位前缀>`、独立 PGlite、全部迁移，finally 关闭 Prisma/PGlite；RS256 私钥仅在测试进程内生成，不落盘。既有文件使用自己的隔离数据库与清理钩子。
- `qa06-evidence.ts` 在断言成功后记录证明；敏感扫描在测试中直接检查原始结果，不先给扫描对象脱敏。扫描器独立于生产脱敏器，发现项仅返回路径/规则，不返回秘密值。
- `run-security-suite.mjs` 在打印子进程输出前扫描，泄漏时拒绝输出原文。报告固定来源 Hash，运行前后不一致即 FAIL；失败写 FAIL 回执，finally 清除临时 trace/report。
- Gate 强制保留 20 文件、19 个关键场景、五项隔离证明、63 个完整管理写接口拒绝矩阵、无越权副作用、四个产物通道及0发现；跳过/失败/缺场景/复用前缀/清理失败/缺通道均拒绝。
- 当前仓库无 `.snap` 文件，回执中的静态 snapshot 清单为空；运行时 JSON 快照和 Vitest 报告已实际扫描。响应/日志/审计扫描数量是采集样本数量，不代表所有可能输出路径已穷举。字段名、JWT/Bearer/私钥/签名 URL 形态与已知 canary 可检测泄漏，未知字段中的任意不透明秘密仍不能仅靠正则识别。

`security-suite.test.mjs` 的正/负测试使用明确的合成报告验证 Gate，不能充当真实执行回执。正式验收记录见 [QA-06 本地验收记录](../audit/QA-06-本地验收记录-2026-10-01.md)。

## 本次防线修复

1. Cognito JWT 必须有 exp；auth_time 必须为正安全整数，且不超出当前时间及配置时钟容差，避免缺过期声明被接受或超范围日期转换异常。
2. Logger/Trace 字段名与审计对齐，覆盖 authorization/cookie/session/jwt；未知字段的裸 JWT 和签名 URL 做值形态脱敏。
3. 审计 before/after 载荷补充签名 URL 值形态遮蔽；同步前端审计显示的字段名镜像，保持既有 parity 回归约束。公钥证书和普通未签名 URL 保留原语义。

这些修复不修改角色、协议枚举或 JWT 正常复用规则。目标服务实跑、真实 Cognito/mTLS/IoT/S3 与负载证据统一在 **QA-09 AWS 隔离测试环境验收**执行；本地安全 Gate 不替代第三方渗透或合规认证。下一开发任务为 QA-07。
