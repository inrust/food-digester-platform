# DEC-006 下行消息序号与幂等

DEC-006 是协议冻结门禁决策（当前 `pending`，登记版本 `0.2.0`）。按《管理后台开发任务清单》§4 末段，本任务把暂定值落地为数据驱动、可整体替换的策略扩展点。**决策本身未冻结，冻结必须经业务方批准人按 [decision-change-template.md](../contracts/decisions/decision-change-template.md) 执行。**

## 暂定值（provisional）

> V1 不强制（下行 `meta.seq`）；Command 以 `meta.id` 幂等。

该暂定值本身可直接执行，且已由 [common.schema.json](../contracts/mqtt/schemas/common.schema.json) 承载：

| 策略面 | 暂定结论 | 承载位置 |
|---|---|---|
| 下行 seq | `cmd` / `notification` / `ota` 引用 `metaBase`，`seq` 可选 | common.schema.json `$defs.metaBase` |
| 上行 seq | 8 个上行 Schema 引用 `metaSeq`，`seq` 必填 | common.schema.json `$defs.metaSeq` |
| Command 幂等 | 幂等键 = `meta.id`（`metaBase` 必填 `id`） | common.schema.json + BE-CMD-02 |

本策略文件（`downlink-policy.json`）将上述行为显式化为事实源，测试强制"策略 ⇄ common.schema.json ⇄ 各消息 Schema 引用"三方一致，防止冻结前被静默默改。

## 使用约束

1. BE-CMD-02 的幂等去重必须以 `meta.id` 为基准，禁止使用 `seq` 或 Payload 内容派生；
2. 下行消息构造不得依赖 `seq` 存在；设备端不得假设下行必带 `seq`；
3. `pendingParameters` 为空：暂定值无待定参数，冻结时若不变更仅需改状态。

## 冻结升级路径

1. 业务方批准 DEC-006（登记升至 `>= 1.0.0`、`frozen`）；
2. 暂定值未变化：`status` 改 `frozen`，提升 `policyVersion` 即可；
3. 若冻结值改为强制下行 `seq`：按 `additive-contract-change` 提升 `common.schema.json` 主版本并同步 `cmd`/`notification`/`ota`。
