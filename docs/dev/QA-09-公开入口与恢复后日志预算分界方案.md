# QA-09 公开入口与恢复后日志预算分界方案

决策：采用原事务公开 `queryRaw` 调用及既有 `withDataPathTrace` 输出回调两处接缝，进入**默认关闭的观测实现**；本轮不接目标环境，不接 compiler 私有钩子。稳定入口、原值/异常、Promise/事务所有权和有界诊断已在离线原型中验证，但自有 observability 的 opaque boundary bridge、生产配置和精确采集器接线尚未实现，`readyToDeploy=false`。该决策不等同候选性能收益或 AWS 验收。

## 接缝及含义

现有 `observeContractLoadDriver` 在 capture dispatch 后，会先关闭并输出 await/prepare 等阶段日志，再执行原 `work()`；故 driver-submit 的55ms并非全部公开 adapter 同步调用。模型恢复回调先开始 result-after-model，再输出 result-to-model；故恢复后的37ms包含部分观察输出。load finally 先 capture end，随后输出终态日志；这些日志可能增加整个 load/API 时间，却在原恢复后窗口之外。

| 点 | 来源/状态 | 可证明范围 |
| --- | --- | --- |
| D：DRIVER_DISPATCH | 已有共享边界 | 原 driver-submit 起点 |
| P：PUBLIC_CALL_ENTERED | 拟议自有观察点；离线已验证同步调用接缝 | 紧邻原 `work()`，不是 compiler 入口 |
| Q：PUBLIC_CALL_EXITED | 拟议点；必须区分原调用返回或同步抛出 | 原 Promise/返回值身份不变；不监听其 then |
| R：ADAPTER_CALL_RETURNED | 已有共享边界 | 原调用返回后，到 driver await 的分界 |
| M：MODEL_EXTENSION_RESUMED | 已有原 await continuation | 开始 result-after-model；不是模型严格完成 |
| E：OPERATION_SETTLED / FAILED | 原 load finally 的 end | 原恢复后窗口结束，随后终态日志在窗口外 |
| Oᵢ：OUTPUT_ENTER / EXIT | 已有 trace 输出回调；拟议 wrapper | 同步 JSON.stringify→redaction→logger.info 返回；不证明 stdout/CloudWatch 已交付 |

```mermaid
flowchart LR
  D[dispatch] --> A[原阶段关闭及日志] --> P[原 work 调用入口] --> Q[原 queryRaw 返回或抛出] --> R[driver 返回边界]
  R --> W[原 driver await] --> M[原模型恢复点] --> L[部分恢复后日志及其他续体] --> E[load end]
  E --> T[原终态日志] --> S[拟议一次摘要]
```

driver-submit 用共享边界拆成 D→P 前缀、P→Q 公开调用、Q→R 返回尾部，三段守恒。output 区间只归属于完整包含它的一个非重叠段；跨边界保留 AMBIGUOUS，无边界保留 UNRESOLVED，窗口外保留 OUTSIDE。不能把日志按自身 phase 名直接归给同名窗口，不能将嵌套 driver/pg、内外层输出重复相加。

仅在诊断完整时计算 `窗口墙钟－窗口内不重叠同步输出区间`，名称为**未归属墙钟界限**；剩余量仍含日志行构造、safeId、边界采样、观察簿记、ALS/调度和其他运行时工作，不是模型/compiler纯成本。CPU为 PROCESS_ALL_THREADS，不做CPU相减，也不把墙钟减CPU解释成等待时间。原始阶段时长、整体 load/API 时长始终保留。

## 已验证的所有权及待实现桥接

稳定外部类型来自锁定版本的公开 `PrismaPg.connect/startTransaction/queryRaw`，源码、声明文件、Prisma生成器/运行时和 lockfile 均绑定到矩阵。离线同步装饰器保留 this/参数及原返回对象，既有 await 单独拥有消费；无新 then/async包装、SQL、事务、pool、重试或强制让步。受控 pg 保留原 load→version update→readback→audit，审计返回id投影仅用于离线。

输出使用真实 JSON.stringify 和 createRedactingLogger，但末端 console 为受控无I/O sink。原回调的返回/异常和递归交付均保留：诊断只阻止自己的递归测量，不吞掉原交付。异步日志后端、真实stdout阻塞和CloudWatch交付成本没有由此测量。

**下一实现必须留在自有模块内：**已有 boundary 对外是不透明对象，测试通过导出接缝的调用括号关联时间，不是可直接复制的生产API。不得导出 WeakMap、私有 trace/Prisma frame 或读取 compiler internals。应在 observability 内部复用原 trace.clock 和 boundary snapshot，通过默认关闭、固定类型的观察端口接收 P/Q 及原阶段边界；按当前 trace 和首个事务 Contract.findFirst 归属，Gateway/Lambda ID分别核对。只传 opaque token/固定枚举，不传 SQL、参数、结果或动态字段。

建议内部端口契约（拟议，尚未实现）：`recordObserverPoint(PUBLIC_CALL_ENTERED|PUBLIC_CALL_EXITED, boundary, outcome)`；phase/output观察和摘要聚合保留在 observability 内。在原 work 前后同步调用固定观察端口，复用原 await；同步抛出记录失败出口，不伪造 ADAPTER_CALL_RETURNED。输出 wrapper 一次调用原输出；捕获自身时钟/CPU/簿记错误并降级，不替换原业务结果/异常。最终只发一次固定摘要，且在原 load 关闭后、不参与自测；摘要本身仍计入完整API耗时。

## 预算及关闭策略

| 项目 | 硬约束 |
| --- | --- |
| 实际默认配置 | 原四候选保持false；拟议 `FDP_CONTRACT_OBSERVER_COST` 默认false，当前未实现 |
| 拟议开启前置 | test、engine/preconnect/detail/public=true、pool1、原首个事务合同读取；前置缺失不得静默开启 |
| 目标资源 | ApiFn512MiB/reserved12/pool1；业务并发≤6；DB静态63≤可用70，不改IAM/KMS/容量 |
| 每请求诊断 | 原首个合同load；≤64个区间，公开调用先预留名额；内存结构有界，无全局请求map |
| 摘要 | 拟议事件 `data-path.contract-load.observer-cost`；最多1条、完整JSON≤4096字节；不得逐区间新增日志 |
| 本轮实际 | 最高19区间、拟议完整摘要777字节；诊断新增输出0、Inspector会话0、网络/数据库服务器/目标夹具0 |
| 本轮子进程 | 固定14组，顺序执行，单组45秒；成功各3事务、失败各1事务；新目录、失败保留、无自动重试 |

关闭路径必须直接返回原输出回调和原值，不读取时钟/CPU，不创建诊断记录。开启时 `TRUNCATED / PROBE_FAILED / FOREIGN_SCOPE / REENTRANT / OUTPUT_FAILED / MISSING_BOUNDARY / DUPLICATE_PUBLIC_CALL` 均保留原业务行为并降级诊断，禁止残差解释；不能用计时器读数失败取代业务错误。记录用尽仍交付每一次原日志，不重试、不新增查询。公开调用/异常与输出所有权用独立Gate判断，不能将业务失败包装为成功验收。

原型只验证逻辑预算及接缝，不证明目标额外RSS、CPU或同步日志耗时可忽略。最终首次load：参考组16.865ms、原型组17.538ms；单次差异不归因、不择优重跑、不宣称低开销。默认关闭实现后，仍须验证其自身捕获/汇总成本与原始API时长。

## 实现及目标入口顺序

1. 实现自有 opaque-boundary 观察端口和一次摘要，追加默认false配置/依赖守卫、Admin hook、部署输入及恢复校验。不得改原阶段边界/日志顺序或迁移模型成本。
2. 补真实入口 JSON/redaction/console调用对照、原错误/Promise/事务所有权、时钟/CPU读取失败、溢出、跨请求、重入、丢边界及摘要预算反例。关闭路径零诊断读数，精确采集器只接受固定event、原request ID和原时间窗；无摘要或重复摘要不能升级PASS。
3. 本地完整验证及本地提交后，由人工通过GitHub Desktop推送。核对同SHA CI/默认关闭部署、19工件和实际开关，再沿用[既有复验手册](QA-09-合同公开运行时接缝与自然冷对照复验.md)的登录、清理、只读容量、未知启动和版本入口规则。
4. 计划 R0 观察关闭→原清理/独立空集→R1 观察开启→原清理/独立空集→关闭恢复。两组固定 engine/preconnect/detail/public=true、**account_read_candidate=true**，仅新增observer开关false/true，以保持已出现425ms窗口的账号原生查询条件，不比较账号预热。关闭恢复时新增observer及原四候选均false；engine沿用已验证恢复设置。
5. 保持原6基线/最多12独立PATCH预算、相同业务/自然冷输入和原只读预算证据，不扩样或重启资源造冷。原始load、Gateway/Lambda/客户端时间和summary成本独立保存；不从摘要残差判断P95收益。

当前 `targetWiring=NOT_IMPLEMENTED`，工作流没有新增开关。以上目标序列是后续实现的验收输入，不是可执行部署命令。本轮 Gate `LOCAL_DESIGN_AND_OWNERSHIP_PASS`；compiler分界、整体QA-09/P95、真实设备HMAC/自然Active/邀请发送和TCP/TLS节点归因没有因本方案升级。
