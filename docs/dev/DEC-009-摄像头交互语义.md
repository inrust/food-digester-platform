# DEC-009 摄像头交互语义

DEC-009 是协议冻结门禁决策（当前 `pending`，登记版本 `0.2.0`）。按《管理后台开发任务清单》§4 末段，本任务把暂定值落地为数据驱动、可整体替换的策略扩展点。**决策本身未冻结，冻结必须经业务方批准人按 [decision-change-template.md](../contracts/decisions/decision-change-template.md) 执行。**

## 暂定值（provisional）

> V1 仅查看最新授权 Media 并手动刷新；实时视频流暂不实现。

全部为定性规则，已可直接执行：

| 策略面 | 暂定结论 | 消费任务 |
|---|---|---|
| 查看范围 | 仅设备已上报且当前授权范围内的**最新** Media 对象；历史查询走 FE-14 Media 列表，不提供时间轴回放 | BE-MED-01、FE-06、FE-12、FE-14 |
| 刷新方式 | 仅手动刷新；禁止前端轮询定时拉取（自动刷新属实时语义） | FE-06、FE-12 |
| 实时流 | **暂不实现**：不提供播放/停止按钮、不接入流媒体协议、不预留 streaming 接口 | BE-MED-01、FE-06、FE-12 |

`pendingParameters` 为空：本决策无待定参数，冻结时若暂定值不变仅需改状态。

## 使用约束

1. FE-06/FE-12 摄像头区域只渲染"最新画面 + 手动刷新按钮"，禁止出现播放/停止控件；
2. BE-MED-01 不提供任何流媒体会话接口；
3. 若未来启用实时流，需先在上级通信协议中定义流媒体能力并新增契约与 Topic（属 DEC-009 冻结变更 + 协议演进，非本策略单独可解锁）。

## 冻结升级路径

1. 业务方批准 DEC-009（登记升至 `>= 1.0.0`、`frozen`）；
2. 暂定值未变化：`status` 改 `frozen`，提升 `policyVersion` 即可。
