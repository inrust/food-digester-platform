## 使用入口

```sh

```

默认业务检查失败关闭：只要完整正式回执或必需专项未齐，退出1，输出QA-09业务PARTIAL。验收入口准备情况使用独立模式：

```sh
node --import tsx scripts/check-qa09-acceptance.mjs docs/audit/evidence/qa-09-a1-entry-2026-10-13/bindings.json --entry-only
```

`--entry-only`只证明A1入口、版本快照、冻结清单和历史证据合并有效；即使退出0，`fullQa09Accepted`和`productionReady`仍为false。它不能替代A8的业务验收。A8必须为剩余专项接入专用验证，不能给库存中的状态字段填PASS来关闭工作。

八个既有领域CLI继续可用。默认保持原隔离环境/HEAD绑定；显式设置`FDP_QA09_BINDINGS`后读取同一经验证sidecar，使用其应用SHA及领域回执路径。例如：

```sh

```

当前没有完整领域回执，该命令仍失败。未来每个`formalReceipts`项必须指定原校验器名称、回执文件摘要、自有创建ID账本文件摘要、独立清理回执摘要。账本与清理必须绑定相同应用/前缀，清理必须绑定账本原字节。业务回执保留真实`isolated=false`，新增`mode=REAL_EXISTING_TEST_ENVIRONMENT`及`runPrefix`。不修改旧回执来补这些字段。

## 三种独立版本

- 应用：`versions.application.sourceCommit/deploymentCommit`绑定目标实际部署的源码和部署；19个不同Lambda的实际工件摘要、成功CI/部署/Amplify及原配置回执继续校验。当前绑定ee8f0713，配置为pool1、512MiB、保留并发12、五候选false，属于已记录目标快照，不表示本次重新读取了AWS。
- 执行器：`versions.executor`使用`CONTENT_SNAPSHOT`，记录真实源文件SHA256及总摘要；`baseCommit`只表示快照来源，不能冒充尚未提交的文件版本。领域校验器、共享入口、范围定义、合并器、相关Schema和环境配置均必需绑定。
- 文档：`versions.documentation`独立绑定本手册、实施报告、当前收口计划和主任务清单的字节摘要。文档变更只更新文档快照，不能偷偷更新应用SHA或把旧业务结果改成当前PASS。

内容快照解决“提交中记录自身提交SHA”的循环；精确文件摘要是实际版本。历史真实执行器继续由各轮原`.sources.json`及封存提交绑定，与本次校验器快照分开。
