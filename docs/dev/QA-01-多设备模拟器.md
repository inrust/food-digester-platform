# QA-01 多设备模拟器

依据：[任务清单 QA-01](../管理后台开发任务清单.md#qa-01-开发多设备模拟器)。前置产物复用 CT-02 Topic Catalog/权限模板、CT-03 Schema/Fixture/RFC8785 hash、[BE-ONB-03 证书包](BE-ONB-03-证书签发与Status-API.md)、[DEC-015](DEC-015-OTA状态回传通道.md)。

## 本地运行

需要仓库 Node 24.12 和已安装的 pnpm 依赖；TLS 测试另外需要 `openssl` 和 localhost 监听权限。

```sh
pnpm qa:simulator docs/dev/fixtures/qa-01-offline.json /tmp/qa-01-offline.json
pnpm test:simulator
QA01_MTLS_RECEIPT=/tmp/qa-01-local-mtls.json pnpm test:simulator
```

CLI 必须提供配置文件和输出 JSON 回执路径。失败退出 1，成功退出 0。回执只有设备 ID、计数和验收范围，不含私钥、证书、下载 URL 或原始消息。默认 `offline` 无网络、无凭据读取，虚拟等待立即完成；10 个独立异步设备各运行 100 轮。并发证书会话的证明由另一个本地 TLS Broker 测试提供。离线的时间间隔表示配置与调度步长，不是实际等待时间证明。

## 配置

配置参考 [qa-01-offline.json](fixtures/qa-01-offline.json)。

| 字段 | 行为 |
| --- | --- |
| `mode` | `offline` 或 `mqtts` |
| `devices` | 至少 10 个不同 `deviceId`；每台设备独立连接与每 Topic 序号 |
| `rounds` | 1～10000 轮 Telemetry |
| `telemetrySeconds` | 整数 10～60 秒，mTLS CLI 使用实际定时等待 |
| `injectFaults` | 每 20 轮额外发一次原消息；第 49/99/... 轮延迟至下一轮之后发送 |
| `disconnectRound` | 指定一轮断开、保留原 Telemetry；下一轮重新连接订阅并补报原消息 |
| `badMessage` | `{ "round": 30, "type": "telemetry" }` 指定 Topic/轮次，将 `meta.seq` 改为字符串，单独违反 Schema 类型规则 |
| `commandResult` | 命令脚本结果 `SUCCESS` 或 `FAILED`，保留下行 `meta.id` 为 `commandId` |
| `otaStatuses` | 默认 DOWNLOADING→INSTALLING→SUCCEEDED；支持合法 FAILED/ROLLED_BACK 分支，拒绝越级脚本 |
| `otaTargets` | 下行 `meta.id` 到原始 OtaTarget ID 的显式映射；缺少映射则失败 |
| `downlinks` | 离线模式注入 `{ type, payload }` 数组；mTLS 模式只消费 Broker 实际下行 |

重复率分母为原始 Telemetry 数量：100 轮产生 5 次额外原文重发，即 5%；2 个较早序号在后一个序号之后到达，即 2% 延迟乱序。其他轮数取完整周期的整数次数；短于周期不承诺精确比例。故障轮次不能与断线轮次冲突，配置会拒绝冲突；断线必须有下一轮可补报。坏消息独立计数，不计入这两个百分比。重复、补报保留原 ID/seq/ts/hash；乱序保留原载荷。合法 Telemetry/Report/Tamper 重算 RFC8785 SHA-256；坏消息也重算 hash，隔离 Schema 错误。

启动发送 Heartbeat/Report/Alarm/Event/Tamper/Media，之后定期发送 Heartbeat/Telemetry。ACK 由 Command/OTA 下行驱动。所有发送/订阅/接收均检查严格自身 Topic、方向和封闭 Catalog，不接受通配符；AWS 实际 QoS 为 1。

## 测试环境 mTLS

本次任务未连接外部服务。未来具备隔离测试环境和独立证书后，可把配置改为 `mqtts`，设置 `environment: "test"`，各设备条目包含：

```json
{
  "deviceId": "YOUR-TEST-THING",
  "endpoint": "mqtts://YOUR-TEST-ENDPOINT:8883",
  "certificatePath": "/private/test-device/certificate.pem",
  "privateKeyPath": "/private/test-device/private.key",
  "caPath": "/private/test-device/server-root-ca.pem"
}
```

```sh
FDP_SIMULATOR_TEST_MQTT=1 pnpm qa:simulator /private/test-devices/config.json /tmp/qa-01-test.json
```

配置中的路径按 CLI 当前目录解析，建议使用绝对路径。缺少 `environment=test` 或显式环境变量时，在读取凭据前拒绝。只接受 mqtts，无用户名密码，强制服务器证书校验。每个设备证书必须匹配私钥；共享公钥直接拒绝。Client ID 等于 Device ID。关闭自动重连；脚本化断线后显式重建连接和三项订阅。Broker 连接/PUBACK 设 10 秒超时；异常下行或权限拒绝使本次运行失败，全部会话最终关闭。

每台设备的证书应来自 BE-ONB-03 APPROVED 证书包：使用 `deviceId`、`certificate.certificatePem` 和 MQTT endpoint；私钥必须仍为本地 CSR 对应私钥。服务器信任 CA 单独提供。模拟器不申请、审批、轮询或反复领取一次性证书包，也不创建云资源。首次合法 Heartbeat 的后端 Onboarded 状态仍需目标环境验证。

真实运行前使用专用测试设备及新 Topic 身份，避免本次进程从 seq=1 开始与以前的设备序号碰撞。当前序号状态不跨进程持久化；回执不用于恢复设备计数器。配置中的 `test` 是操作门禁，不能证明 endpoint 属于测试账号；由运行者核对隔离环境。

OTA publisher 使用 `OTA-${targetId.toUpperCase()}` 作为下行消息 ID；该值不能直接作为原始 `otaTargetId`。需在 `otaTargets` 中登记对应关系。OTA 只通过自身 `ack` 的 `objectType=OTA_TARGET` 上报封闭五状态；没有第二 Topic 或 IoT Jobs 通道。模拟器不下载/安装固件，不模拟传感器精度或实体安全互锁，Media Fixture 不代表真实上传文件。

## 验收与边界

[本地验收记录](../audit/QA-01-本地验收记录-2026-10-01.md)与两份 JSON 回执区分离线注入和本地真实 mTLS。测试检查所有正常载荷 Schema/hash、100 条唯一 Telemetry、精确重复/乱序率、原文补报、命令/OTA 关联隔离、关闭清理、配置负向和客户端跨设备权限拒绝。

本地 TLS Broker 用临时 CA 签发 10 张独立证书，验证 10 个 Device ID 并发会话、断线后重连、QoS1 PUBACK、3 类下行及 Broker 侧跨设备订阅/发布拒绝；结束删除临时私钥。Broker 是测试实现，其 ACL 结果不能替代 AWS IoT Policy 验收。AWS、后端 Quarantine/幂等/归档、Onboarded 落库与实际 10～60 秒长时间负载均没有本次目标回执，后续由 QA-03/隔离环境验证。
