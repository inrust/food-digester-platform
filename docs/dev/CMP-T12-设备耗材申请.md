# CMP E/T12 · R20 设备耗材申请

## 候选协议

复用设备 REST 的 API Gateway mTLS 及 AUTH-03 证书绑定。设备端候选入口为 `POST /api/v1/device/consumable-requests`，版本为 `1`，默认关闭。设备及客户来自证书验证与当前分配，服务端要求设备为 Active，客户及站点有效，事件发生在当前分配生效后且不晚于服务端收件时间。耗材类型使用 DEC-008 的枚举。候选入口的请求、响应和错误结构见 [OpenAPI](../../contracts/rest/device-consumable-request-candidate.openapi.json)。

以下为受控夹具，`clientVersion` 是本地测试标识。实际设备构建及对应版本由联调确认。

```json
{
  "schemaVersion": 1,
  "clientVersion": "t12-controlled-uplink.1",
  "requestKey": "offline-id",
  "consumableType": "CARBON_FILTER",
  "occurredAt": "2026-08-28T12:00:00Z",
  "note": "滤芯达到更换条件"
}
```

设备端应持久化申请标识与申请内容。离线补报、重启恢复、超时或 5xx 重试沿用该标识及原始内容。服务器按设备和申请标识去重，比较标准化后的协议版本、类型、发生时间及备注。即使工单已完成，合法重试仍返回原工单 ID。

| 响应 | 设备端处理 |
| --- | --- |
| 201 `CREATED` | 保存返回的工单 ID 并结束上报。 |
| 200 `LINKED_OPEN` / `REPLAYED` | 保存返回的工单 ID 并结束上报。已有同客户同耗材的开放工单时关联该单，保留其来源和阶段备注。 |
| 400 | 记录请求错误，修正格式或版本后再提交。 |
| 401 / 403 / 404 | 记录认证、准入或入口可用性问题，等待条件恢复。 |
| 409 `IDEMPOTENCY_CONFLICT` | 核对已保存的申请内容。新业务申请使用新标识。 |
| 409 `CONFLICT` | 核对设备生命周期、当前分配及工单状态。已变更分配的历史事件不能归入新客户。 |

设备新建工单记录 `DEVICE` 来源，申请备注写入 T05 的申请阶段。关联已有开放工单时，关联事件及设备备注写入该次操作审计。处理、完成、取消仍沿用 T05 的 If-Match、状态机和阶段备注。既有 ADMIN 工单继续支持查询、处理、完成和取消。

## 验证与切换

- 本地证据使用受控证书、PGlite 和管理后台浏览器夹具，覆盖候选路由、重复及离线提交、同标识冲突、新旧来源并行、阶段读回以及平台发起入口的切换与恢复。
- 实际设备与目标环境均为 `NOT_RUN`。联调需要取得可识别的设备端构建、双方确认此候选契约和重试语义，并具备目标环境验证授权、可用 mTLS 凭据及已分配的测试设备。用实际设备验证发起、离线补报、重试及后台处理、完成后的逐阶段读回，再确认各设备批次和旧管理端的兼容窗口。
- 设备端候选配置 `DEVICE_CONSUMABLE_REQUEST_TARGETS` 使用设备 ID 到已确认构建版本的 JSON 映射。空映射或未配置时维持关闭。验证完成且确认兼容窗口后，可设定 `ADMIN_CONSUMABLE_REQUEST_CREATE_UNTIL` 为 UTC 截止时间。管理端列表从配置生效起提示页面隐藏发起入口，旧端创建 API 在截止时间前仍可用，到达截止时间后拒绝创建。
- 回退时清除管理端截止时间，恢复平台发起入口及旧端 API。需要关闭设备受理时清除设备准入映射。已保存的设备申请标识及工单历史继续可读，设备再次开放后可沿用原标识重试。
