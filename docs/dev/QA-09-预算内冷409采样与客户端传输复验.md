## 执行预算与语义

`run-qa09-nonactive-target --cold409-sampling`仍先执行五角色基础和原三轮合同竞争（6个PATCH，原合同v1→4断言不变）。成功后另建最多6个本轮DRAFT合同；分两批，每批3合同，每个合同各两个If-Match=1 PATCH同时派发，批内最大并发6，采样PATCH总数12，批间先完成readback/审计后再继续。加原基线共18个PATCH、7个DRAFT合同；不是12个总写请求，也不提高AWS保留并发12/pool1预算。每对必须一成功一VERSION_CONFLICT，版本仅1→2、名称等于胜者；每个请求均匹配成功/失败审计。未知写入不得重试，等待全部兄弟请求及35秒Lambda静默窗口，再读回或清理。

采样业务PASS与冷态PASS分开。原child/parent/wrapper、业务数据库指纹、设备/客户/站点/身份和归档清理继续保留。父执行器在采样模式必须检查child最终PASS，采样台账、计数、合同归属和审计均通过才生成业务执行PASS；其cold409Gate仍NOT_EVALUATED。禁止将此执行Gate当作冷样本验收。

## 客户端传输观测

合同基线与采样模式开启Node HTTPS单次派发，进程共享keep-alive Agent最多6个socket，不自动重试、不跟随重定向、不绕过TLS证书验证。其余模式保留既有fetch行为。UUID在建立连接前写入台账。

| 字段 | 边界 |
| --- | --- |
| socketAcquisitionMs | transport开始至分配socket，包含Agent排队，不是服务器连接池等待 |
| dnsMs / tcpMs / tlsMs | socket lookup/connect/secureConnect事件的间隔；未发生或复用连接为null，不填伪造0 |
| requestSentAtMs | 本机request finish事件，不表示服务器已收到 |
| headersAtMs / responseWaitMs | 收到响应头的时间与request finish后间隔，包含网络/Gateway/Lambda，不是纯服务端耗时 |
| firstBodyAtMs / bodyEndAtMs / bodyReadMs | 第一块响应体、完整响应体和读体间隔 |
| jsonParseMs | 完整读体后的JSON解析；非法JSON仍为失败 |
| phase / reusedSocket | 当前传输阶段及Node标记的连接复用 |

时间使用本机单调时钟，毫秒舍入；IP直连可能没有DNS事件。各相对时间字段不能与独立测得的Lambda阶段直接相加。总20秒AbortSignal覆盖头及响应体；失败保留已知HTTP/Gateway ID、transportPhase和clientTransport.phase，不保存URL、Authorization、请求头/响应头全集、Cookie、Token、DNS地址或证书。第三方fetch注入不得冒充详细socket观测。
