# DEC-003 一次性证书包领取策略

DEC-003 是协议冻结门禁决策（当前 `pending`，登记版本 `0.2.0`）。按《管理后台开发任务清单》§4 末段，本任务把暂定值落地为数据驱动、可整体替换的策略扩展点。**决策本身未冻结，冻结必须经业务方批准人按 [decision-change-template.md](../contracts/decisions/decision-change-template.md) 执行。**

## 暂定值（provisional）

> KMS 加密短期保存；成功领取后销毁；丢失后重签。

| 策略面 | 暂定结论 | 消费任务 |
|---|---|---|
| 存储 | KMS 信封加密、短期保存；明文私钥永不落库；日志/审计只记录指纹 | SEC-01、BE-ONB-03、BE-CERT-02 |
| 领取 | 一次性；成功领取后立即销毁密文包；冻结前重复领取失败关闭（拒绝） | SEC-01、BE-ONB-03、BE-CERT-02 |
| 丢失处置 | 重签新证书包（不恢复旧包明文） | SEC-01、BE-ONB-03、BE-CERT-02 |
| 销毁触发 | 成功领取；新证书首个合法 Heartbeat（轮换确认） | SEC-01、BE-ONB-03、BE-ONB-04、BE-CERT-02 |

## 待冻结参数（fail-closed）

DEC-003 的核心未定项是**定量参数**，本策略以 `null` 显式标记，读取即抛 `PolicyParameterPendingError`，禁止臆测默认值：

- `storage.retentionSeconds`：证书包短期保存时长（秒）；
- `claim.maxClaims`：允许领取次数（冻结前重复领取一律拒绝）。

## 使用约束

1. 消费方（SEC-01、BE-ONB-03、BE-CERT-02、BE-ONB-04）只能经 `certificate-package-policy.ts` 查询；
2. SEC-01 可实现信封加密、一次性领取、销毁与脱敏的完整机制，但不得为 `retentionSeconds`/`maxClaims` 选定数值；
3. `status: provisional` 期间，数据库 Schema 不得把保存期限/次数固化为不可迁移的约束。

## 冻结升级路径

1. 业务方批准 DEC-003（登记升至 `>= 1.0.0`、`frozen`）；
2. 在 `certificate-package-policy.json` 填入冻结数值，`status` 改 `frozen`，提升 `policyVersion` 并同步 `x-decision-versions`；
3. 消费方代码无需修改（数据驱动）。
