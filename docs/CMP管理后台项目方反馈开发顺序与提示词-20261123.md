# CMP 管理后台项目方反馈开发顺序与提示词

2026-11-23 · 产品方案已确认 · 开发待启动

本轮按工作包 0、A–G 实施，覆盖 R01–R20，合计 **29–47 人日**。单人按任务表从上到下执行。多人按前置任务并行，先交付可以独立验收的关键修复，再切换业务入口和设备协议。人日不含等待设备联调窗口的时间。 [已确认的开发计划](CMP管理后台项目方反馈与开发规划-20261123.md)

## 2. 共用提示词

每次启动一项任务时，复制本段及对应的单项提示词。

~~~text
在 food-digester-platform 仓库实施下方指定的单项 CMP 任务。先读 AGENTS.md、docs/CMP管理后台项目方反馈与开发规划-20261123.md 第 4 节及本执行文档，核查当前分支、工作树、前置提交和实际代码。以 R 编号追踪需求，并在提交说明中注明工作包和任务。

复用现有页面、控制器、Ant Design、i18n、路由守卫、共享 RBAC、租户约束与业务状态机。新增写路径沿用服务端鉴权、现有并发保护与审计。涉及 API 或设备协议时同步更新契约、运行时路由与回归测试。涉及数据修改时验证旧数据读取、部分失败、重试、并发及版本切换。

运行适用的管理后台类型检查、定向 Vitest 和 Playwright 用例。变更接口时运行 pnpm openapi:check，并验证影响到的契约。用受控数据记录结果，区分本地、目标环境和实际设备验证。按仓库约定提交并推送，报告提交 SHA、R 编号、检查结果与实际发布状态。未运行的检查标 NOT_RUN，写明外部联调阻塞和具体条件。
~~~

## 3. 单项开发提示词

### T00 基线复现与截图核对

~~~text
建立 2026-11-23 反馈基线。记录实际管理后台构建、管理 API 和用于测试的设备或模拟器版本。用受控数据复现离线仍显示正常、合约草稿导航、已停用账号与站点、设备用户归属和耗材备注覆盖。对照《当前问题20261123.docx》第 3、7、9 页、docs/index19.html 和当前路由，记录受影响控件及现有入口。确认 T12 示例值对应的地域字段。若只能取得附件文字或环境不可用，登记未核实项，并用源码、原型及本地场景为可独立实施的任务建立基线。
~~~

### T01 顶部账号详情与设备离线状态

~~~text
实施 R01、R03。从 Topbar.tsx、会话已验证邮箱与本人资料接线开始，账号详情显示与顶部一致的名称、角色显示名及已验证邮箱。覆盖邮箱缺失、邮箱未验证、长名字、键盘与焦点返回。

检查 DeviceViewPage.tsx 和 device-console/service.ts。沿用 DEC-024 连接判定，把在线状态、最后上报和部件数据时效明确呈现。设备离线或数据过期时，将已有部件值标明为带时间的历史值，空数据给出从未上报状态。测试无心跳、阈值边界、断线、历史正常值及新心跳恢复。复验 CMP-01 的名称和键盘交互。
~~~

### T02 平台账号启用与停用反馈

~~~text
实施 R07、R08。接通账号启用的管理 API、服务端权限、Cognito 适配器和 SettingsPage 操作。复用现有账号停用的意图、补偿与审计口径。定义已停用且未完成邀请账号的恢复状态，验证真实身份系统与业务记录最终一致。对停用、启用、刷新和重复请求给出确定的读回结果。

授权管理员可在停用行使用“启用”。成功使用现有 Toast 并自动消失，文案显示“账号已停用”或“账号已启用”。验证无权限、重复提交、并发状态变化、Cognito 失败或部分成功及重新登录。
~~~

### T03 合约业务日期与草稿导航

~~~text
实施 R11、R13、R14 和 R12 的过渡提示。从 ContractNewPage.tsx、ContractDetailPage.tsx、contract-state.ts、合约 handler 与 service 入手。新建、编辑、续约输入业务日期，固定 Asia/Shanghai，开始日 00:00 起算，结束日含当天，用次日 00:00 作为排他边界换算 UTC。旧调用可继续传现有时间戳，UTC 精确时间和未编辑日期的边界原样读写。列表和详情按业务日期显示。验证同日起止、月底、闰日、显示时区切换、续约和设备关联窗口相邻或重叠。

允许已保存草稿离开当前页，从详情继续关联。提供候选空、查询失败和重试路径，确认离开或重进无重复创建。把 Eligible 改为“可关联设备”等业务用语，原因显示为“关联原因（必填）”。在表单内客户录入上线前提示如何选择已建客户。
~~~

### T04 设备用户归属读回

~~~text
实施 R10。以创建时显示名与客户 ID 不同的数据复现。逐层检查 DeviceUsersPage.tsx、设备用户控制器、请求体、详情 DTO、持久化及列表。确认归属字段来自同一客户关系，用授权范围内的客户名称展示“所属客户”，账号名称和设备分配字段独立。覆盖旧记录、名称不可用、权限不足、详情刷新和请求竞态。为 T07 提供可复用的详情与客户标签逻辑。
~~~

### T05 耗材分阶段备注与提示

~~~text
实施 R20 的备注和操作反馈。从 request-service.ts、耗材 DTO、数据模型及 ConsumablesPage.tsx 入手。将申请、处理、完成、取消的备注按阶段独立保存和呈现，沿用 PENDING、PROCESSING、COMPLETED、CANCELLED 状态机及乐观锁。保留旧字段的读取兼容。仅按可靠审计证据回填历史阶段及备注来源。

处理确认说明进入“处理中”及处理备注要求。完成确认说明关闭工单及完成备注要求。用备注值不同的单据证明各阶段读回无覆盖。验证重复或并发操作、取消、权限不足、旧单据和移动端对话框。预留 T12 的设备来源接入点。
~~~

### T06 设备导航与媒体告警配置入口

~~~text
实施 R04 的导航部分、R05、R06。比对 routes.ts、路由守卫和 contracts/prototype-traceability.yaml。设备侧栏提供“查看设备、操作设备、设备群管理、耗材查看”。从设备群进入配置工作台，从设备详情进入单设备配置或媒体，媒体请求固定使用已校验的设备 ID。从概览进入告警与事件，从设备详情进入本设备相关告警。沿用告警确认与媒体预览下载权限。

旧直达链接有设备上下文时导向同一设备，无上下文时引导选择或进入新工作台。验证面包屑、返回后的筛选、旧告警证据链接、媒体跨页采集时间排序、直接访问和越权拒绝。配置 JSON 的交付和回执由 T11 完成。
~~~

### T07 合约授权与单设备用户

~~~text
实施 R10 的设备上下文、R15、R17。将授权管理接入合约详情，服务端校验合约与设备关联、当前角色和客户范围。无适用合约的存量授权从设备详情进入，继续提供获授权的读取、签发、续期、撤销和审计。校验关联变动后迟到响应与过期操作。

把设备用户列表、详情和允许的写操作接到单设备管理，移除平台页中的跳转。明确新增后是否已分配以及分配失败时能否重试，区别解除当前设备分配和停用整个账号。测试同客户不同设备、不同客户、只读角色、旧链接和直接加载。
~~~

### T08 平台用户页与业务设置入口

~~~text
实施 R18 的页面整理。将菜单、面包屑和页标题统一为“平台用户管理”。整理 SettingsPage 及控制器，设备用户由 T07 的设备页承接，业务设置移到独立的受权限控制入口。复验告警阈值与命令确认等实际消费方、设置读写权限、审计和旧链接。继续使用 T02 的启停反馈。两类平台角色的邀请及分配限制由 T13 实施。
~~~

### T09 合约内录入客户

~~~text
实施 R12、R16 的客户流程。复用现有 Customer 主键和合约关系，在创建合约的表单内显式区分“选择已有客户”和“新建客户”。新建客户与合约在同一业务事务提交，保留既有客户及合同写权限和审计。设计重试与唯一合同编号冲突的响应，在同名客户存在时提供明确选择。验证创建失败回滚、重复提交、旧客户、旧 API、草稿续办以及接入流程选择客户。新流程验证后隐藏独立客户菜单并移除前置提示。旧客户链接按权限导到可用业务入口。
~~~

### T10 Onboarding 录入站点与站点维护

~~~text
实施 R02、R09、R16 的站点流程。沿用 DEC-011 和 Customer → Site → Device 关系。设备获批并达到可分配状态后，由具备首次分配权限的管理员在接入的业务分配步骤选择客户、选择或录入站点、区域和子区域。沿用接入审批、发证与设备分配的状态边界。支持失败重试、老设备补录和同一客户范围内显式复用同名站点。调整共用站点时说明影响设备范围。

在接入和设备管理的上下文中提供站点查找、编辑、重新启用及合规软删除。增加恢复 API，复用 If-Match、审计和已有删除约束。验证停用站点须恢复后才可分配、有关联设备不能删、删除与分配冲突、无关联旧站点可查，以及变更后设备详情、地域与联动筛选一致。替代入口验证后隐藏独立站点菜单。
~~~

### T11 版本化 JSON 配置交付上位机

~~~text
实施 R04、R19。对照 docs/index19.html、DEC-018、现有配置服务和设备 Sync，形成原型字段、载荷字段、单位、默认值、必填和支持版本的映射。先用合约样例和上位机联调版本确认 JSON Schema、兼容和回执，再启用目标设备。合约、区域、站点和别名从业务实体读取。

优先复用 CONFIG_CHANGED 与设备 Sync；确保老设备按现有字段运行，新设备按已验证的版本接收 JSON。UI 明确通知、已交付与已应用，应用状态依赖可关联到设备和配置版本的回执。测试错误载荷、同群不同配置、目标校验、离线补拉、旧客户端、旧书签以及回退。联调未取得时记录实际设备验证状态，兼容路径继续可用。
~~~

### T12 厨余机发起耗材申请

~~~text
实施 R20 的设备来源。依据现有设备认证及上行能力，与设备端确定载荷、版本、申请标识、错误和重试响应。设备身份以服务端认证事实为准，校验设备生命周期、归属和耗材类型。用设备与申请标识去重，覆盖重复上报、离线补报、标识冲突及新旧来源并存。

复用 T05 的阶段备注和工单状态机。用设备端联调版本从发起到后台处理、完成全链路读回。验证全链路后移除平台发起操作，按已验证的兼容窗口限制旧管理端创建 API。保留存量 ADMIN 工单的处理、取消和查询能力，验证切换与回退。
~~~

### T13 双角色交付及存量兼容

~~~text
实施 R18 的双角色行为。盘点现有 Cognito 组、业务角色、邀请、分配、菜单、API 权限和回归账号。平台用户管理的新邀请与角色分配候选仅显示“平台管理员”及“运维人员”，映射 PlatformSuperAdmin 与 PlatformOperator。平台权限视图按两类交付角色展示。平台写入路径在服务端落实候选约束，客户账号管理按既有作用域运行。

保留已有 Auditor、CustomerAdmin、CustomerViewer 及其会话和权限，兼容已有多角色账号和审计记录。验证禁止自动升权、旧身份可按权限查看、各角色直达路径、租户隔离、禁用与重新启用。交付前回归 CMP-37 的权限矩阵与既有审计路径。
~~~

### T14 集成验证与项目方走查

~~~text
执行 R01–R20 联合验收。按下方发布顺序记录前端构建、API 提交、数据迁移、设备协议与上位机版本。在发布候选执行 pnpm verify，用测试环境和受控设备验证对应场景。逐项登记角色、环境、数据、步骤、实际结果和脱敏证据。按新口径回归 CMP-01、19、31、34、37、42 及受影响的媒体排序和配置版本链路。

对未实测的目标环境和设备链路标 NOT_RUN，对未满足的交付依赖标 BLOCKED 并注明责任方与所缺条件。完成项目方走查后登记实际结论。必要时按工作包验证入口或协议回退，保留已写入业务数据及审计证据。
~~~

## 4. 发布顺序

| 批次 | 范围 | 切换条件 |
| --- | --- | --- |
| 第一批 | A 关键流程和数据问题 | 独立完成账号启停、合约日期与导航、状态显示、归属和备注回归后部署。 |
| 第二批 | B 对象入口、C 客户与站点、F 双角色 | 兼容 API 与数据变更先部署。设备、合约和平台各新入口验收后，逐项收起对应独立菜单。角色变更通过存量身份和租户验证后启用。 |
| 第三批 | D 配置和 E 设备耗材 | 两条设备链路可分开发布。各自用联调版本和目标数据确认端到端行为及回退方式，再切换设备协议和旧入口。 |
| 签收 | G 联合回归 | 汇总三批候选的版本、逐项证据及项目方结论。 |
