# 上位机业务激活操作指南

适用于已完成首个合法 MQTT Heartbeat、设备生命周期已为 `Onboarded` 的上位机。管理员负责分配客户和站点、发布配置、签发并激活 License。上位机负责同步、应用配置和本地验签。 [Onboarding API](./api/onboard-api.bio-nexa.com.md) · [MQTT 联调说明](./api/iot.bio-nexa.com.md)

自 DEC-027@1.0.0（2026-11-11）起，管理员激活有效 License 时，云端会在同一事务中将满足条件的设备从 `Assigned` 或 `Licensed` 置为 `Active`。上位机通过普通 Sync 获取结果。`licenseConfirmation` 仅用于兼容旧客户端的 `RECEIVED` 和 `VERIFIED` 请求，新客户端使用 `lastSyncTime` 即可。 [现行 Sync 契约](./api/device-api.bio-nexa.com.md#post-apiv1devicesync) · [云端自动激活说明](./dev/License-云端自动激活.md)

## 1. 分配客户和站点

1. 使用平台超级管理员账号进入 **设备管理 → 设备群管理**，按设备序列号找到台账。在该设备的操作列点击 **管理**，确认详情中的序列号并记录平台 `deviceId`。
2. 点击 **分配/调整归属**，选择客户和该客户名下的站点。需要记录操作背景时可填写分配原因。
3. 点击 **确认分配**。在设备详情中核对客户、站点和分配历史，确认生命周期从 `Onboarded` 进入 `Assigned`。

设备群管理通过平台 `deviceId` 打开管理详情。首次分配从设备台账进入，远程命令页「操作设备」的设备选择器依赖已有的站点归属。 [设备群管理](https://admin.bio-nexa.com/devices/groups) · [设备生命周期操作](./dev/FE-07-Device生命周期操作页面.md)

## 2. 创建并发布设备专属配置

1. 进入 **设备管理 → 配置管理**，点击 **新建配置**。填写配置名称，目标类型选 **按设备**，填入步骤 1 记录的平台 `deviceId`。
2. 打开配置详情，点击 **新建版本**。核对下表中的四项设置，按需调整后点击 **创建版本**。
3. 对该草稿点击 **发布 → 确认发布**。需要立即生效时留空生效时间。核对目标设备、已发布版本和生效时间。

| 设置           | Sync 字段               | 平台默认值 |
| -------------- | ----------------------- | ---------- |
| 心跳间隔       | `heartbeatInterval`     | 60 秒      |
| 遥测间隔       | `telemetryInterval`     | 30 秒      |
| 摄像头刷新间隔 | `cameraRefreshInterval` | 1 分钟     |
| 温度阈值       | `temperatureThreshold`  | 80 °C      |

Sync 优先选择该设备已发布且已生效的版本，其次选择匹配的型号配置。没有匹配版本时返回 `"configuration": null`。配置页的**同步状态**显示通知投递状态，上位机实际收到并应用的值由设备方核对。 [配置管理](https://admin.bio-nexa.com/configurations) · [配置页面说明](./dev/FE-09-Configuration与DeviceUser页面.md)

## 3. 创建、签发并激活 License

1. 进入 **合约管理 → 授权管理**，点击 **新建授权（Draft）**。选择已分配的设备，填写有效期起止日期，按实际业务需要选择远程控制（`REMOTE_CONTROL`）、OTA（`OTA`）或 ESG 报告（`ESG_REPORTING`）权限，提交草稿。
2. 打开该 License 的 **详情**，核对设备、客户、有效期和权限，点击 **签发 → 确认签发**。云端生成签名，License 变为 `Issued`。
3. 在同一条记录上点击 **激活 → 确认激活**。激活要求 License 已在有效期内，且设备存在与该 License 客户匹配的当前有效客户和站点分配。核对 License 为 `Active`，再到设备管理详情核对设备生命周期为 `Active`。

已有生效的 `Active`、`ExpiringSoon` 或 `Renewed` License，而设备仍为 `Assigned` 或 `Licensed` 时，先让上位机执行一次普通 Sync。云端会按当前证书、License 有效期和签名、客户及站点归属补齐激活。已有 `Issued` License 时，继续在后台激活该记录。 [授权管理](https://admin.bio-nexa.com/licenses) · [License 页面说明](./dev/FE-08-License与Entitlement页面.md) · [云端自动激活说明](./dev/License-云端自动激活.md)

## 4. 上位机 Sync、应用配置和本地验签

1. 使用当前有效的设备证书和本地私钥，通过 mTLS 调用 `POST /api/v1/device/sync`。首次 Sync 可发送 `{"lastSyncTime": null}`，后续传入上次成功取得的快照时间 `snapshotAt`。收到 `CONFIG_CHANGED` 或 `LICENSE_CHANGED` 通知后可立即同步。
2. 核对响应的 `deviceId`、`assignment.customerId`、`assignment.siteId` 和 `configuration`。按收到的四项配置调整设备的上报与运行参数。
3. 核对 `license.licenseId`、`version`、`effective` 及 `signaturePayload` 中的设备、客户、有效期和权限。按 DEC-020 使用获权验签材料，对 `signaturePayload` 对应的规范载荷执行 HMAC-SHA256 校验。签名格式为 `v1.<base64url(mac)>`。规范载荷使用完整的 UTC 时间戳和排序后的权限值，字段顺序按 DEC-020 执行。
4. 设备方记录此次 Sync 的 `snapshotAt`、`etag`、License ID、版本、配置应用结果和本地验签结果，并向管理员反馈。管理员在 Sync 响应中核对 `operationalStatus.lifecycleStatus = "Active"`。本地验签结果以设备方实际校验记录为准。

## 常见问题

| 现象                                                      | 核对项                                                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 「操作设备」页选不到新接入的上位机                        | 到「设备群管理」按序列号查台账，从操作列的「管理」进入并完成站点分配。                                 |
| Sync 的 `assignment` 为 `null`                            | 核对目标设备是否已完成客户与站点分配，及上位机当前证书对应的 `deviceId`。                              |
| Sync 的 `configuration` 为 `null`，或上位机显示四项为 `0` | 先看原始 Sync 响应，再核对配置目标、版本状态和生效时间。                                               |
| License 已激活，设备仍为 `Assigned` 或 `Licensed`         | 先执行普通 Sync，再核对 License 有效期、签名、设备及客户绑定、当前站点分配，以及设备是否已挂起或退役。 |
| 云端显示设备为 `Active`，但上位机验签失败                 | 核对 `signaturePayload` 的完整 UTC 时间戳、权限顺序、签名格式和获权验签材料。记录设备端实际失败结果。  |
