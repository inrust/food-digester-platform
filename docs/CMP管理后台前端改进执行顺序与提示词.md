# CMP 管理后台前端改进执行顺序与提示词

2026-11-19 确认产品方案。本次开发覆盖项目方的 44 项反馈，按[开发计划](CMP管理后台前端改进开发计划.md)中的 A–E 工作包安排。人日为工作量，具体日历取决于投入人员及联调窗口。下列任务均处于待开发状态。

## 1. 开发顺序

| 顺序 | 工作包 | 开发任务 | 前置任务 | 交付条件 |
| --- | --- | --- | --- | --- |
| T01 | A | 通用弹窗及关闭故障 | — | 七处反馈对应的弹窗可退出，提交与取消行为可验证 |
| T02 | A | 新增设备请求详情与拒绝流程 | T01 | 详情点击即见，拒绝后列表和详情状态一致 |
| T03 | A | 设备查看、操作设备查询与按钮重叠 | — | 设备查询可用，命令目标一致，两处筛选按钮可操作 |
| T04 | A | 耗材设备校验与设备 ESG 重置 | T01 | 无效设备无法创建申请，重置后的列表和导出范围一致 |
| T05 | B | 各页面筛选与快捷操作布局 | T03、T04 | 公共筛选布局一致，各页保有正确的查询与重置行为 |
| T06 | B | 设备、配置、告警与站点详情 | T01、T05 | 详情可发现，版本历史有界，原有业务操作可用 |
| T07 | B | 合约、授权、账号、权限矩阵与审计布局 | T01、T05 | 各类详情及用户表格可读，高权限操作和脱敏规则通过回归 |
| T08 | C | 媒体采集时间跨页排序 | T05 的媒体筛选布局 | API 与游标支持升降序，前端和旧客户端兼容 |
| T09 | D | 落实顶部栏、授权、设置与设备用户入口决定 | T07 | D1–D4、D6 的确认行为逐角色通过回归 |
| T10 | C | 配置生效时间及按设备展示版本 | T06、T09 | 时间与 UTC 来回转换正确，生效版本和通知状态可追溯 |
| T11 | C | 顶部账号身份与概览设备区 | T09 | 可读账号名、身份 ID 与设备卡片口径正确 |
| T12 | E | 集成回归和候选版本验收 | T01–T11 | 44 项均有逐项结果和证据，遗留差项有明确状态 |

单人按表顺序实施。多人可在 T01 开始时独立推进 T03，T08 的 API 与契约可在 A 阶段并行启动，前端排序在 T05 的媒体布局合入后接线。T06 与 T07 可并行，T10 与 T11 可并行。T01–T04 合入后先验证 P1 链路，再集成其余任务。涉及 API 变化的任务先验证兼容性和接口，再启用前端入口。

## 2. 共用提示词

每次开工时复制本段和下方对应任务的提示词。

~~~text
在 food-digester-platform 仓库实施下面指定的一个 CMP 任务。先读取 AGENTS.md、docs/CMP管理后台前端改进开发计划.md 和执行顺序文档，检查当前分支、工作树、前置任务的合入提交及目标代码。使用清单中的 CMP 编号追踪，按已确认的产品行为实施。

沿用现有 Ant Design 组件、页面控制器、i18n、路由权限和租户边界。涉及写操作时保留服务端权限、If-Match 或已有并发约束、原因与审计。按任务范围补充回归用例，运行相关 Vitest、管理后台类型检查和适用的 Playwright 用例。改动 API 时同步更新 OpenAPI、服务与契约测试，保留旧客户端兼容性。用合成或批准的测试数据记录证据。

完成后按仓库约定独立提交，并在本次执行获得的 Git 权限范围内推送。报告 CMP 编号、提交 SHA、执行过的检查和结果。用 NOT_RUN 标记未运行的检查，用 OPEN 或 BLOCKED 记录遗留项及原因。本地验证与目标环境实测分别给出证据。
~~~

## 3. 各任务提示词

### T01 通用弹窗及关闭故障

~~~text
实施工作包 A 的 CMP-28、29、30、33、36、39 及 44 的关闭问题。

从 Modal.tsx、dialog-a11y.ts 和 ConfirmDialog.tsx 定位通用行为。修复合约关联设备、编辑、续约、业务设置编辑、角色分配、设备用户修改资料和审计详情七个入口。提供可见关闭按钮，交互表单保留取消，验证 Escape、Tab 和焦点返回。嵌套对话框仅关闭最上层。空候选、校验失败和请求失败时可退出。取消后重开时读取当前保存值，测试关闭和取消均不会触发写请求，原因、角色、版本及保存反馈均正常。审计详情内容布局由 T07 实施。
~~~

### T02 新增设备请求详情与拒绝流程

~~~text
实施工作包 A 的 CMP-11、12。使用 T01 完成的弹窗行为。

将 OnboardingReviewPanel 的详情从列表下方改为点击即打开的详情弹窗，在其中处理加载、成功、错误和待审批动作。审批确认层可独立取消。拒绝成功后关闭详情，刷新当前待审批列表，并在已拒绝标签读回状态。拒绝失败时保留详情并给出可重试提示。测试切换标签、快速切换选中记录、关闭弹窗与迟到响应，确认旧详情不会重新出现。保留拒绝原因、版本校验和批准后的导航流程。
~~~

### T03 设备查询及筛选按钮重叠

~~~text
实施工作包 A 的 CMP-05、06、08、26。

检查 DeviceViewPage、DeviceOperatePage、ContractsPage 及其控制器。查看设备页明确应用的启用条件，验证已分配和缺少地区标签设备的可选路径，按当前角色范围提供可用设备选择、加载和失败提示。操作设备页增加“查询设备”，把选择草稿与已应用目标分开。在草稿改变、加载或报错时收紧命令入口，命令请求只使用当前确认的设备。修复命令状态中的筛选按钮与命令下拉、合约筛选按钮与客户下拉的重叠。测试长中英文标签、小视口、切换设备时的迟到响应和命令目标标识。
~~~

### T04 耗材设备校验与设备 ESG 重置

~~~text
实施工作包 A 的 CMP-19、25。

在新建耗材更换申请中使用权限范围内的设备选择，并在字段附近反馈设备无效或提交前已失效。以服务端校验为最终判定，验证不存在、未分配、已退役、越权、合法设备和重复申请。设备 ESG 提供一个完整重置路径，清空可编辑设备范围、起止日期和日期错误，重置已应用查询与分页，保留固定 Customer 范围。验证查询及导出的实际请求参数，覆盖应用后重置、重置后导出及重置后重新查询。
~~~

### T05 筛选与快捷操作布局

~~~text
实施工作包 B 的 CMP-07、09、13、18、20、22、24、40、43。

从 ScopeFilter 和现有筛选样式入手，对齐标签与输入、控制最小宽度和换行，给查询与重置保留独立操作区。应用到设备群、耗材、告警、媒体、ESG 概览、站点及审计日志。处理设备群双重重置，保持查询参数和分页一致。将配置页“新建配置”移至工具栏最左侧。按类别整理设备快捷操作和不可用原因。复验 T03 的两处重叠及 T04 的 ESG 重置。以中英文和长值测试表单可读性，核对无障碍标签、固定租户范围和各页实际查询语义。
~~~

### T06 设备、配置、告警与站点详情

~~~text
实施工作包 B 的 CMP-10、14、15、21、41。

按现有详情数据组织页面。设备管理详情按四轴状态及生命周期、配置、OTA、备注、证书和分配历史分区。配置方案区分摘要、目标、派生信息和版本历史，版本按需展开并在多版本时控制高度，历史版本仍可访问。告警详情突出状态和发生、清除信息，证据图片入口及确认、清除操作保留权限。站点从表格直接打开弹窗或抽屉，关闭后恢复滚动位置和焦点，验证存在编辑和停用权限时的交互。覆盖空数据、错误、长内容、键盘操作和若干已有版本。实际生效版本的数据对接由 T10 实施。
~~~

### T07 合约、授权、账号与审计布局

~~~text
实施工作包 B 的 CMP-27、32、35、37、38 及 44 的详情布局。

合约详情组织摘要、期限、联系信息、关联设备及历史，复验编辑、续约与关联入口。保留独立 License 详情，按设备、有效期、Entitlement、状态变更和操作分区。规范平台用户表格列宽、长值查看与操作列。权限矩阵采用共享 RBAC 定义，按模块和角色提供只读查看及查找。设备用户详情区分账号、分配、通知与实际应用确认。审计详情展示事件及脱敏前后值，长 JSON 可在容器内滚动。测试不同角色、只读状态、长内容、脱敏和 T01 的关闭交互。
~~~

### T08 媒体采集时间跨页排序

~~~text
实施工作包 C 的 CMP-23。

检查 GET /api/v1/admin/media 的 handler、service、OpenAPI、前端媒体页和分页状态。API 增加可选采集时间方向，缺省保留旧客户端的 ID 升序。带排序参数时按 captureTime 和稳定 ID 排序并使用组合游标，验证游标方向及旧游标兼容性。前端通过采集时间列切换升序和降序，进入页面时最新优先，换向或筛选变动从第一页重新请求。用固定测试数据验证双方向相邻页、相同采集时间、切换方向、非法参数、旧客户端及租户边界。根据查询计划确定是否需要组合索引。保留下载授权与过期行为。
~~~

### T09 顶部栏与导航决定落地

~~~text
实施工作包 D 的 CMP-03、04、31、34、42。

隐藏未接数据的顶部铃铛。显示时区仅提供 Asia/Shanghai 和 UTC，延续登录默认上海，并处理旧伦敦、纽约等偏好回退。保留独立授权管理入口、现有角色及审计。业务设置展示四项现有设置及用途、消费方、运行时状态和可编辑性，以 API 和实际消费方为准。确认 alarm.thresholds 由 FE-18 消费的范围、command.confirmation 的运行时作用，以及两个 STORED_ONLY 项的说明。将用户管理中的设备用户页签改为按权限进入 /device-users 的跳转入口，避免打开用户管理时重复加载设备账号列表。用五种角色验证菜单、直达路径、编辑权限、两种时区及旧偏好。
~~~

### T10 配置生效时间与按设备版本

~~~text
实施工作包 C 的 CMP-16、17，并落实 D5。沿用 T06 的配置详情和 T09 的时区选择。

发布版本时使用带时区说明的日期时间选择器，按当前显示时区转换为 UTC，空值沿用发布即生效，非法时间或格式阻止提交。按设备展示云端当前生效的配置方案与版本并说明来源，复用设备 Sync 的配置解析口径。分别展示各版本的 CONFIG_CHANGED 通知状态。设备实际应用版本只读可信回执，缺少匹配回执时标未知。覆盖跨日转换、未来生效、设备定向优先、型号定向的多设备及无配置。接口若需扩展，先定义分页、权限和空状态，用设备和版本级数据验证结果。
~~~

### T11 顶部账号与概览设备区

~~~text
实施工作包 C 的 CMP-01、02。沿用 T09 的顶部栏结构。

确认当前凭据中可用的可读名称及业务 displayName 的安全来源。顶部正常显示可读名称，长值截断并可查看全文，完整用户 ID 经可访问入口查看。覆盖已有账号和字段缺失的回退，明确业务 userId 和登录标识的来源。概览区说明设备总数与卡片预览的关系，展示当前可见范围及最多 10 台，按现有设备 ID 排序。加入按角色可达的设备列表入口。验证平台、客户、长名称、0 台、少于与多于 10 台，以及两种语言和窄视口。
~~~

### T12 集成回归和候选版本验收

~~~text
实施工作包 E。以计划中的 CMP-01 至 CMP-44 作为验收索引，确认 T01 至 T11 的提交已进入同一候选。核对分批验证、前端构建 SHA、API 版本和生效契约。

先运行管理后台类型检查、定向 Vitest、Playwright 回归及变更接口的 OpenAPI 验证。重点检查查询目标、弹窗退出、审批拒绝、重置与导出、耗材设备校验、媒体同时间跨页排序、配置版本及五种角色的访问范围。获得目标环境及测试材料后，在对应候选版本上复验中英文、典型视口及键盘交互。用 CMP 编号登记结果、复现步骤和证据链接，保留失败与未执行结果。按实际结果提交项目方走查材料，列明影响发布的待办和对应回退版本。
~~~
