## 1. 实施基线和依赖

| 项目 | 已确认值 |
|---|---|
| 预览启停 | REST 查看租约，每页一个 viewerId，多页面共享设备 streamId |
| 设备查询 | 每 5 秒读取查看状态，仅启用该能力的设备执行 |
| 帧上传与页面读取 | 默认各 2 秒一次，服务端最多每秒接收一张新帧，每个客户端最多一个在途请求 |
| 租约与帧有效期 | 租约 30 秒，每 10 秒续租；帧最长 10 秒，结束租约后立即停止对外可见 |
| 帧规格 | JPEG，默认长边 640 px，原图最多 128 KiB，请求最多 180 KiB，解码尺寸按接口设计约束 |
| 事件告警图片 | 每条触发消息一张，通过 triggerRef 引用原 MQTT meta.id |
| 归档限制 | 沿用图片 10 MiB、上传 URL 900 秒、每设备每日 100 个上传会话 |
| 异步关联 | PENDING → LINKED 或 UNMATCHED，登记后最多等待 24 小时 |

仍需实施阶段补齐的输入是设备能力启用方式、业务拍照白名单、预计启用设备数、同时查看数、首帧等待验收目标和目标环境测试材料。这些输入分别在任务中收口，允许先开展契约及本地功能开发。真实设备版本、证书和云环境部署窗口由对应负责人提供。这些外部实施输入不作为本次云端接口包交付前置，不要求本仓库取得 App 源码或承担真机验收。

既有 [DEC-009 摄像头策略](../dev/DEC-009-摄像头交互语义.md) 为手动刷新，须依据本次确认升级决策版本、策略及消费者。现有 MQTT media 字段可继续用于归档，新关联字段进入 REST 上传会话。计划中的文件名和模块拆分为实施建议，具体按现有模块边界落地。

## 2. 阶段任务

### P0 固化契约与技术落点

依赖已确认接口方案。完成本阶段后，设备方即可按相同样例开发。

| 编号 | 执行动作 | 交付与完成条件 |
|---|---|---|
| IMG-01 | 升级 DEC-009 与摄像头交互策略，将设计参数变为可执行契约。定义预览能力开关的来源与缺省关闭语义 | 决策登记、策略版本和消费者追踪一致。旧设备及未开启能力的设备保持可接入 |
| IMG-02 | 为五个预览路由建立设备和管理 OpenAPI，完整定义各状态、错误体与样例。扩展上传会话 triggerRef、200 重用和 409 已登记响应，扩展查询 evidenceImage | 契约与 SDK 类型可生成，封闭对象及可选字段兼容旧请求。明确无 media:read 时省略 evidenceImage，具备权限且未匹配时返回 null |
| IMG-03 | 确定共享临时存储和原子并发方案，优先评估 DynamoDB 条件写与事务。验证租约集合、streamId 代次、帧替换、去重摘要和限频的原子边界 | 记录选型及本地并发验证。显式按逻辑时间校验过期，TTL 清扫只回收数据。写入帧时与最后租约释放并发也不能重新暴露旧帧 |
| IMG-04 | 定义持久数据迁移、关联任务和对外样例 | 上传会话保存不可变 triggerRef 与文件申报；触发引用有唯一约束；区分图片登记状态和关联状态。设备方拿到真实 JPEG/Base64 正负向向量及 S3 签名头示例 |

IMG-03 同时定义取消分配、客户迁移、挂起和退役后的失效机制。租约和帧需带租户及授权代次，读写均核验当前归属，旧租约续租失败，新客户获得新 streamId。记录授权撤销与在途请求的可见性边界并加入并发用例。

### P1 云端实时预览

依赖 IMG-01 至 IMG-03。以一个设备和一个查看者跑通，再扩展多查看者。

| 编号 | 执行动作 | 交付与完成条件 |
|---|---|---|
| IMG-05 | 实现查看租约申请、续租、释放和设备 state 查询 | 租约绑定用户与设备，多页面共享 streamId，最后租约失效后停止可见；已到期租约可幂等释放 |
| IMG-06 | 实现帧上传、Base64 与 JPEG 校验、原子替换、去重、限频 | 旧帧不能覆盖新帧，近期重复提交不延长截止时间，同 ID 异内容冲突；超限和坏图按设计拒绝 |
| IMG-07 | 实现平台 latest 查询及权限、过期判定 | READY 带 Base64，UNCHANGED 省略图片体，WAITING_FRAME 省略帧；无有效查看租约和跨租户不能取图 |
| IMG-08 | 接入真实运行入口及 IaC 定义 | 路由登记、设备与管理 Lambda 组合根、CORS、依赖注入、共享存储权限及日志脱敏完整。多实例读取同一状态，存储故障返回明确错误 |

代码主要落在 `apps/cloud-api/src` 下的预览业务模块和既有 `runtime` 装配、`packages/aws-clients/src` 存储适配及 `infra/src` 资源定义。新增文件应与现有包依赖规则一致。

图片大小和计数上限在读入、解码前后分别检查。JPEG 解码库需有解码尺寸及资源约束，拒绝损坏图像。缓存物理回收时间与逻辑过期时间独立配置。帧内容、Base64、设备私钥和临时 URL 均不进入日志。

### P2 云端事件告警图片关联

依赖 IMG-02、IMG-04，完成后可用模拟设备验证 S3 业务流程。

| 编号 | 执行动作 | 交付与完成条件 |
|---|---|---|
| IMG-09 | 实施向前兼容数据库迁移，保留历史记录可读性 | 原有无关联会话和 MediaObject 可继续使用，迁移可重复验证，唯一键及索引支撑按触发引用查找 |
| IMG-10 | 扩展上传会话服务 | 同触发同申报有效重试复用会话和原到期时间；改变申报冲突；过期可新办，已登记返回 mediaId；并发重试不重复消耗配额 |
| IMG-11 | 在 Media 登记事务内创建关联记录，并通过既有 Outbox 方式可靠调度解析 | 对象、大小和 Hash 验证成功后才建记录。重复 MQTT、旧会话与新会话竞争最多产生一个有效触发关联，失败事务可重试 |
| IMG-12 | 实现关联解析与定时重试 | 同租户同设备按 sourceMessageId 匹配；首轮立即尝试，PENDING 每分钟扫描可重试项，24 小时截止。重复、并发执行幂等，分批分页，有终态和失败原因 |
| IMG-13 | 扩展告警详情与事件查询 | 已关联返回 evidenceImage，经现有下载 URL 获取 S3 图片；告警清除后保留关联，媒体删除后显示 DELETED，权限不足不泄露 mediaId |

代码主要复用 `apps/cloud-api/src/media`、`packages/media/src`、`apps/ingestion-worker/src/media`、告警事件查询模块，以及 `packages/database/prisma`。关联重试优先复用仓库已有任务调度和 Outbox 机制，避免只依靠进程内定时器。

会话重用时，重签 URL 的截止时间不得超过原会话期限。图片已入 S3 但元数据未登记的恢复流程，要区分等待消费、会话到期和新会话替换。到期旧对象的清理仅处理已确认失效且未登记的自有上传对象，并记录失败重试。原告警或事件未能处理时，图片转 UNMATCHED，供运营按原因排查。

## 3. 执行顺序与阶段完成条件

1. 执行 IMG-01 至 IMG-04，交付契约及设备方对接包。首个开发提交覆盖决策和契约，形成 G0。
2. 执行 IMG-05 至 IMG-08，用模拟设备跑通预览，形成 G1。
3. 执行 IMG-09 至 IMG-13，用模拟消息与文件跑通两种触发关联，形成 G2。
4. 执行 IMG-14 至 IMG-18，平台和设备分别接入。平台模拟联调可先完成，真机证据等待设备方交付。
5. 执行 IMG-19、IMG-20，达到 G3 本地集成完成。
6. 目标环境条件就绪后执行 IMG-21 至 IMG-24，分别形成 G4 真实云端和 G5 真机验收。
7. 每个阶段提交可独立审查的变更，并按仓库规则推送。阶段报告逐项记录 PASS、FAIL、NOT_RUN 和 BLOCKED。
