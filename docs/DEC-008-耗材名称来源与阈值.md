# DEC-008 耗材正式名称、数据来源与阈值

DEC-008 是协议冻结门禁决策（当前 `pending`，登记版本 `0.2.0`）。按《管理后台开发任务清单》§4 末段，本任务把暂定值落地为数据驱动、可整体替换的策略扩展点。**决策本身未冻结，冻结必须经业务方批准人按 [decision-change-template.md](../contracts/decisions/decision-change-template.md) 执行。**

## 暂定值（provisional）

> 暂用 `CARBON_FILTER`、`BIO_ADDITIVE`；仅保存设备已定义上报值，不由云端臆测百分比。

| 策略面 | 暂定结论 | 消费任务 |
|---|---|---|
| 类型代码 | 封闭集合：`CARBON_FILTER`、`BIO_ADDITIVE`；新增类型必须先走决策冻结或版本升级 | DB-01、BE-IOT-05、BE-CNS-01、FE-18 |
| 数据来源 | 仅设备上报（原始值原样入库）；云端不得推算剩余百分比/寿命；未上报维度显示未知 | BE-IOT-05、BE-CNS-01、DB-01 |
| 展示 | **正式名称与阈值待定**（`null`，fail-closed） | FE-18、BE-CNS-01 |

## 待冻结参数（fail-closed）

- `display.names.*`：各类型正式展示名称（读取抛 `PolicyParameterPendingError`）；
- `display.thresholds.*`：各类型展示/告警阈值（读取抛 `PolicyParameterPendingError`）。

冻结前 FE-18 显示类型代码原文并标注待定，**不得使用原型名称（碳包/活性菌等）**。

## 使用约束

1. BE-IOT-05 仅落库设备已定义上报值，任何云端推导字段禁止入库；
2. BE-CNS-01 / FE-18 对设备未上报的维度返回/显示"未知"，不得填充估算值；
3. 未知耗材类型查询抛 `UnknownConsumableTypeError`（失败关闭）。

## 冻结升级路径

1. 业务方批准 DEC-008（登记升至 `>= 1.0.0`、`frozen`）；
2. 填入正式名称与阈值，`status` 改 `frozen`，提升 `policyVersion` 并同步 `x-decision-versions` 与 prototype-traceability.yaml；
3. 若类型代码变更，需同步 DB-01 枚举与 BE-IOT-05 校验。
