## 实现

`run-qa09-nonactive-target.mjs`保留已验证的版本、五角色 SRP、受控数据库、业务依赖清理、夹具外基线与域归档清理路径。`nonActiveOnly`不能进入包含 Active 依赖探针的完整波次，完整设备许可证生命周期探针明确 NOT_RUN。

新增合法路径包含 Operator 设备别名/客户更新、站点创建/更新/停用，CustomerAdmin 设备用户密码轮换，以及管理端 License Draft→Issued→Active→Revoked。服务端 License Active 与设备自然生命周期 Active 分开记录，许可证路径结束后再次回读设备状态。

浏览器使用真实 admin.bio-nexa.com 与 api.bio-nexa.com，真实 SRP登录，无 API mock、无角色 session 篡改；执行375/1440两个视口，记录接口方法、路径、状态、Gateway requestId、DOM哈希及限定的合约新建表单截图。

117项 Adopt/Adapt 映射40个实际行为组；11项 Defer/Reject 单独登记，任何失败也阻断浏览器 Gate。两个视口均有通过回执才将该组元素记为 PASS。缺少本轮实体或实际数据的分支不能由可见控件代替验收。

63写接口 × 五角色独立登记。`HTTP_SUCCESS_OBSERVED`只表示合法请求2xx回执；业务持久化仍须关联显式回读和数据库回执。它不代表全部63接口或所有许可角色写操作完成。

首轮业务与设备/证书基线保持一致，清理 PASS；本轮8个License域归档版本已清除。CORS只读 OPTIONS探针两个自有路径均为204，允许正确Origin、PATCH和If-Match；未调整Gateway配置。
