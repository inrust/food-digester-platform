## 2. 严格 Gate 设计

### 2.1 响应契约

`openapi-response.ts` 从版本化 `contracts/rest/openapi.bundle.json` 按 operationId、HTTP status 定位实际 response schema，并让 AJV 对完整值执行 required、枚举、类型、嵌套 `$ref` 和 `additionalProperties` 校验。Lambda 字符串 body 必须先能解析为 JSON；测试调用方没有提取 `data` 或手工复制 required 字段的旁路。

### 2.2 生产路由

`delivered-operations.ts` 是本范围生产适配器实际消费的路由事实表，覆盖：

- Onboarding API：2 个 operation；
- Device API：Certificate Status/Rotate、Sync、Deactivate 共 4 个 operation；
- Admin API：Onboarding 管理 4 个 operation及 Certificate Rotation Request 1 个 operation。

`check:runtime` 从六份目标 OpenAPI 反向建立 operation 集合，与上述 11 项按 operationId、method、path 双向比较。任一侧缺失、额外、重复或漂移均令 `pnpm verify` 失败。

### 2.3 已交付 Lambda

CDK synth 后，Gate 检查 Ingestion、Outbox Publisher、Certificate Package Sweeper、Onboarding Deadline、Retirement Timeout、Onboarding API、Onboarding Provisioning、Device API 和 Admin API 共 9 个 Lambda。逻辑资源缺失或 `Code.ZipFile` 内联占位均失败；范围外尚未宣称交付的 Lambda 不被误标为完成。

## 4. 剩余风险与发布边界

- P0、P1、P2 的本地实现与严格 Gate 已分别闭环，但没有把“本地通过”表述为“目标 AWS 已验收”。尚缺 mTLS 自定义域、IoT/KMS、EventBridge、RDS 并发及设备实际收包的部署后证据。
- `check:runtime` 当前有意只覆盖本报告任务范围内已经声明交付的 11 个 operation；其他管理 API 随对应 BE 任务接入生产后，应显式加入生产路由事实表或建立同等级分域登记。
- CDK asset Gate 证明合成模板引用真实部署包，不证明真实账号中的 IAM 允许/拒绝行为或运行时依赖可用；发布前仍须在隔离 AWS 环境执行并保存证据和清理回执。
