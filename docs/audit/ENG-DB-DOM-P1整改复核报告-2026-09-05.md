## 4. 风险分析与后续建议

### 4.1 剩余风险

| 等级 | 模块 | 风险 | 处置建议 |
|---|---|---|---|
| 低危 | DB-01 | 旧 `device_state_history` 数据在历史实现中已丢失 axis，无法无歧义恢复；Migration 保守回填为 `lifecycle` | 部署前统计旧记录；如存在可验证来源，另建一次性校正脚本并保留变更审计 |
| 低危 | DOM-03 | 当前值形态脱敏覆盖 PEM；JWT、更多通用 Token 和循环对象策略仍属于 SEC 后续加固 | 在 SEC 任务增加封闭样本与确定序列化策略 |
| 低危 | 工具链 | 本机默认 Node 24/pnpm 11 不属于仓库声明范围，会显示 engine 警告 | 开发和 CI 使用 `.nvmrc` 与 `packageManager` 固定版本；不要把警告环境作为发布证据 |

### 4.2 后续建议

1. CI 明确安装 Node 20.19.5 与 pnpm 10.20.0，并执行冻结锁文件安装和 `pnpm verify`。
2. 生产 Migration 前对历史状态记录做数量与来源盘点，确认保守回填影响。
3. P2 文档维护采用“命令 + 当次快照日期”记录测试数量，避免把易漂移数字作为永久结论。
