### 2.2 BE-ONB-01～04

本轮重新核对了 Onboarding Request、管理员审批、Provisioning/Status、首个 Heartbeat 与超时链路。聚焦实现、契约、生产 Lambda、EventBridge 调度、KMS/IoT 权限和 PGlite 并发/失败恢复测试均与既有整改结果一致，未发现新的活动缺陷。

本结论仅接受“本地仓库可部署闭环”。API Gateway、RDS、KMS、IoT 和 EventBridge 在目标 AWS 账户中的真实权限、网络和时序仍为发布前运行 Gate。

### 2.3 BE-CERT-01

通过项：当前 mTLS 证书身份限定、ACTIVE/EXPIRING/EXPIRED/REVOKED 推导、UTC 日期和边界测试、响应不读取 PEM/私钥。

未通过项：

1. `createCertificateStatusHandler` 返回 `{data,meta}`，而 `device-certificate-api.json` 的 200 Schema 直接要求 `CertificateStatus` 顶层对象；实际设备响应无法通过该 OpenAPI。
2. 无 Device API Lambda 组合根或路由调用该 Handler，CDK 的 Device API 实际指向只支持 Cognito 管理端 Onboarding 的 `ApiFn`。

### 2.4 BE-CERT-02

通过项：currentCertificateId 与 mTLS 身份核对、AWS 发证/Policy/Thing attach、双证书窗口、首个新证 Heartbeat 撤旧证与销包、密钥材料不进入普通列或审计。

未通过项：

1. 实际成功响应使用 `{data,meta}`，OpenAPI/源稿要求五字段顶层对象；`effectiveDate` 实现返回 ISO 时间戳，契约要求 UTC `YYYY-MM-DD`。
2. 成功响应提交并销包后，在新证首个 Heartbeat 前再次用旧证调用 rotate，会把刚交付的新证标记 REVOKED 并再次签发；重复执行可持续制造新证书，违反“重试不产生无限证书”。现有测试只覆盖“响应未确认”重试，没有覆盖“响应已成功提交”重放。
3. Handler 未拒绝未知请求字段，与 OpenAPI `additionalProperties:false` 不一致。
4. 无生产 Device API 组合根、AWS/KMS 依赖注入、响应提交回调适配和路由。

### 2.5 BE-CERT-03

通过项：仅 PlatformSuperAdmin 持有 `certificate:rotate`、生命周期/ACTIVE 证书资格门、PENDING 请求及并发幂等、Outbox 与审计同事务、管理响应无密钥材料、OpenAPI 与模块响应形态一致。

未通过项：

1. `runtime/lambda-entry.ts` 只构造管理员 Onboarding Handler，`createAdminRoute` 也只识别 `/admin/onboarding/requests`；轮换请求路径在生产入口返回 404。
2. Service 只保证 `CERTIFICATE_ROTATION_REQUIRED` 写入 Outbox；CDK 的 `OutboxPublisherFn` 没有生产 entry，仍部署 501 占位 Handler，无法证明 Notification 被实际发布一次。

### 2.6 BE-SYNC-01

通过项：lastSyncTime 封闭解析、六域全量聚合、Active/Suspended/Maintenance 同步节奏、Retired 72 小时内仅 Sync 例外、租户隔离、稳定域 ETag 与敏感材料控制。

未通过项：

1. 实际 Handler 返回 `{data: snapshot, meta}`，OpenAPI 和解析文档要求六域顶层快照。
2. License `status` 直接返回数据库的 `Active/Expired`，OpenAPI/源稿要求 `ACTIVE/EXPIRED`；`validFrom/validTo` 返回 ISO 时间戳，契约要求 `date`；`OTA_UPDATE` 未映射为源协议 `OTA`。
3. “契约一致性”测试只取 `response.body.data` 并检查键名存在，未用 OpenAPI Schema 校验整个 HTTP body，也未检查 enum/format，因此上述冲突仍然绿测。
4. 无生产 Device API 组合根和路由。

### 2.7 BE-SYNC-02

通过项：Retired + PENDING_CONFIRMATION 门禁、确认与撤销 ACTIVE 证书同事务、重复确认重放、审计脱敏、实际 `{data,meta}` 与当前 OpenAPI 一致。

未通过项：

1. 源稿/OpenAPI 定义无请求体，但 Handler 完全忽略 `req.body`，任意请求体仍返回成功，不是严格无请求体契约。
2. `evaluateRetirementTimeouts` 虽有领域实现和单测，但全仓只有导出和测试引用；没有 Lambda entry、EventBridge 计划或其他生产调用方。超过 DEC-014 的 72 小时后，证书不会自动撤销，也不会产生 `UNCONFIRMED_TIMEOUT` 审计。
3. 无生产 Device API 组合根和路由。

### 3.6 综合风险判断

当前最大风险不是 Service 逻辑缺失，而是“模块实现和测试存在，但正式入口不可达”。其次是源协议与实际 Handler 响应分叉；这会在生产接线后立即暴露为设备解析失败。证书轮换重放和退役超时未接线涉及证书生命周期安全，不能作为普通文档债务延后。

全仓静态 Gate 与单元测试通过，只证明各自覆盖范围内没有失败；它们未证明 operation-to-route 完整性、实际 HTTP body 符合 OpenAPI 或目标 AWS 环境可用。

## 4. 整改建议

### 4.1 P0：先解除阻塞

1. 新建独立 Device API Lambda 生产组合根，注入数据库、AUTH-03 mTLS identity、IoT/KMS、DEC-001 Maintenance 间隔等依赖；显式路由 certificate status/rotate、sync、deactivate，并让 API Gateway Device API 只集成该 Lambda。
2. 扩展 Admin Lambda 组合根和路由表，接入 BE-CERT-03；补生产级 operation-to-handler 测试，要求所有正式非 planned OpenAPI operation 均有唯一真实路由。
3. 为 Device Lambda 建立响应提交回调语义，确保 Rotate 的 `confirmDelivery` 仅在 JSON 序列化成功后执行，失败时不返回含私钥的 200。

### 4.2 P1：修复协议和证书生命周期

1. 以解析文档和当前 OpenAPI 为准：Certificate Status/Rotate、Sync 返回顶层载荷；Rotate `effectiveDate` 改为 UTC date；Sync 映射 License 状态为大写枚举、日期为 `YYYY-MM-DD`、`OTA_UPDATE` 为线协议 `OTA`。
2. 重构 BE-CERT-02 的交付状态机，区分“从未封包失败”“响应已预留未确认”“响应已成功提交但未 Heartbeat”；成功提交后的重复请求必须稳定幂等/冲突，不得自动撤销已交付的新证并无限重签。
3. 为 `evaluateRetirementTimeouts` 增加独立生产 entry、最小权限 Lambda 和 EventBridge 调度；补 CDK 断言及部署后演练，验证精确 72 小时边界、并发 Deactivate/force-complete 和 `UNCONFIRMED_TIMEOUT` 审计。
4. 为 Outbox Publisher 接入真实生产 entry 和 MQTT/IoT Data Plane sender，补 `CERTIFICATE_ROTATION_REQUIRED` 从事务 Outbox 到设备 Topic 的集成测试。

### 4.3 P2：补齐严格验收能力

1. 用 JSON Schema/OpenAPI response validator 校验完整 Handler/Lambda HTTP body，不允许测试先手工剥离 `data` 再验证。
2. 增加负向用例：Certificate Rotate 未知字段、Deactivate 任意请求体、成功提交后重复 Rotate、Device API 无 Bearer JWT 但有有效 mTLS、超时调度存在且调用正确 Service。
3. 扩展 `check:cdk` 或新增 Gate，拒绝已声明交付任务的 Lambda 使用 `PLACEHOLDER_HANDLER_CODE`，并比对 OpenAPI operationId 与生产路由清单。
4. 修复 BE-CERT/BE-SYNC 开发说明中的链接、决策状态和生产接线陈述；文档须分别标注模块验证、生产接线、本地严格验收与目标 AWS 运行验收。
