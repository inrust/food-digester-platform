## 修复内容

`FDP-CloudFormationExecutionPolicy.json`（权限授予）及 `FDP-DeploymentBoundary.json`（权限上限）新增 `ManageLiveImageTables`：仅允许这两张表的创建、读取、更新、删除、TTL、PITR 和标签管理。没有授予表内数据读写、跨表权限或 `dynamodb:*`。

权限清单同时覆盖 AWS 当前 `AWS::DynamoDB::Table` schema 的 read handler：`DescribeTable`、`DescribeContinuousBackups`、`DescribeContributorInsights`、`DescribeKinesisStreamingDestination`、`ListTagsOfResource`、`GetResourcePolicy`、`DescribeTimeToLive`。本轮通过 CloudFormation `describe-type` 只读获取该 schema；参见 [AWS 表资源说明](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-dynamodb-table.html)与 [DynamoDB 权限参考](https://docs.aws.amazon.com/service-authorization/latest/reference/list_dynamodb.html)。未启用的导入、复制、Kinesis、资源策略写入不在本次授权范围。

`FDP-ServiceBoundary.json` 新增 `AllowLiveImageItemAccess`，仅允许两张表上的 `GetItem` 和 `PutItem`。应用角色仍由 CDK 各自的 identity policy 决定实际可用权限；边界不直接授予权限。现有合成测试检查：所有 DB Lambda 仅获得 CONTROL fencing 权限；只有两类 API 获得 payload 权限，管理 API 的 payload 权限只有读取。
