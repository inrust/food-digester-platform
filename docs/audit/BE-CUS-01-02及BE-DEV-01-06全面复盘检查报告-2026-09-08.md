### 3.6 风险归纳

1. **可交付性风险（最高）**：代码在库内，但不在部署入口内；任何基于局部测试的“已完成”结论都会直接误判。
2. **安全风险**：退役设备的 AWS IoT 凭证和 MQTT 数据面未按 DEC-014 闭合；导出任务在设备转租户边界会固化错误授权。
3. **数据一致性风险**：alias 唯一性没有数据库级并发保证。
4. **证据风险**：OpenAPI lint、PGlite、mock S3 signer、CDK synth 均不是目标 AWS 运行验收。

## 四、整改建议

### P0：恢复真实可交付路径

1. 扩展 `DeliveredOperation.method` 以支持 PATCH/DELETE，将本次 25 个 OpenAPI 操作纳入唯一生产路由事实表；在 `lambda-entry.ts` 实例化并注入 Customer、Site、Device、Assignment、Status、Retirement、Console/Export Handler。
2. 为每个 operation 增加 API Gateway 事件→生产 Router→真实 Handler 的组合根测试；路径参数需覆盖 URL decode，Customer scope 不得从 query 或 authorizer 伪造。
3. 将 runtime Gate 的单独 OpenAPI 白名单改为可审查的“已交付 manifest”，或对正式合并 OpenAPI 全量双向比较；新增负向用例：声明一个未接线 operation 必须使 Gate 失败。
4. 为 BE-DEV-05 增加真实 Worker 入口与触发机制，接入独立 S3 前缀、最小 IAM、对象生命周期和真实预签名器；对 PROCESSING 超时增加租约/恢复，避免 Worker 崩溃后永久卡住。

### P0/P1：关闭安全与并发缺口

5. 按 DEC-014 将退役完成拆为可恢复的持久化意图：DB 确认、AWS IoT `UpdateCertificate(INACTIVE)`、结果回写与失败重试必须可辨认；给 Deactivate/force/timeout 的执行角色授予最小 IoT 权限并测试中途失败。同时在 Ingress 身份/授权层明确拒绝 Retired 的 8 类业务 MQTT，不能只依赖 REST AUTH-03。
6. 导出创建时固化 `to = createdAt`，并在 Worker 和下载时二次校验设备当前归属/授权；如需允许转租户前历史导出，应对 Event/Alarm 使用事件时 Customer 归属快照，而非只按 deviceId 查询。
7. 先冻结 alias 长度、Unicode/大小写规范化和唯一性语义，再增加与其一致的 DB 表达式/部分唯一索引；增加两设备并发改同名的真实 PostgreSQL 负测。

### P1/P2：契约与证据闭环

8. 对所有写请求使用共享的严格 Schema 验证，在业务写入前拒绝未知字段和错误类型；用真实 Handler 响应反向校验 OpenAPI，不只检查 JSON 文件本身。
9. 完成以上整改后，先运行本报告的定向集合，再运行全量 `pnpm verify`；当前工作区的前端 lint 失败须与本后端范围分开处理，但发布前全仓 Gate 仍必须绿。
10. 在隔离 AWS 测试环境留存可复核回执：25 个 API 的正/负路径、Cognito 五角色与跨 Customer、If-Match 竞态、IoT 退役窗口/真实撤证、S3 导出及 URL 过期；记录账号/区域/时间/版本与清理回执。
