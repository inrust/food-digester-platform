## 3. 仍需处理的风险

| 优先级 | 模块 | 表现/影响 | 下一步 |
|---|---|---|---|
| 阻塞 | 证书/truststore | 尚未提供真实 ACM ARN、受控 Bucket 与已上传 CA 的 VersionId；真实配置无法预检/部署 | 另行批准证书/CA 准备，并只读核验有效性 |
| 阻塞 | AWS 环境 | Bootstrap、Stack、Amplify、Migration 未执行；本地模板不能替代真实验收 | 最终 diff/费用/初始化 SHA 审批后分阶段执行 |
| 高危 | DNS | 使用生产命名可能覆盖已有服务；尚未核验记录占用 | 核验所有权与现状，单独批准切换，不本轮写 DNS |
| 高危 | 数据库 | 测试级 Single-AZ，无备份/删除保护；迁移失败不能自动恢复 | 不引入真实业务数据；失败只读诊断后重新批准 |
| 高危 | 构建授权 | 可覆盖 CodeBuild buildspec/角色/源码的操作者有潜在 Secret 执行权限 | 实际 IAM 限定项目、源码前缀并禁止未批准 overrides；记录批准工件 hash/version |
| 中危 | TLS | 本地仅证明严格参数配置，未做真实错误证书/主机名负测 | 目标环境执行 TLS 负测，缺失时不宣称安全验收 PASS |
| 中危 | 预算/外部服务 | 预检已显示现有费用；SES/webhook、Amplify 来源仓库未确定 | 确认成本来源、发信验证和来源配置后再申请部署 |

本轮未新增 MQTT `iot.bio-nexa.com` DATA Domain Configuration、Amplify App、DNS 记录或客户 Web。迁移项目无自动触发/重试，日志保留两周；源码 Bucket/日志 RETAIN 需要测试清理时显式处理。

## 4. 整改与执行建议

先提交批准的本地变更，确定准确源码 SHA；再核实 DNS、费用与所需权限，准备同账号同区域 ACM 和外部 CA 对象版本。之后审批最终 CDK diff 与部署费用边界，依次 Bootstrap/Deploy、按固定 S3 VersionId 手动启动 Migration、配置 Amplify/Cognito 并执行真实浏览器与 AWS 验收。任何目标回执均绑定实际部署 SHA，不沿用本轮基线作为已部署证明。

操作输入、域名映射、Runner 命令及边界详见 [AWS测试环境部署配置与执行手册](../AWS测试环境部署配置与执行手册.md)。此前 [首次部署预检记录](AWS测试环境首次部署预检记录-2026-09-15.md) 是当时只读快照，不改写成部署成功记录。
