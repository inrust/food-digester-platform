## 4. 整改与维护建议

当前无须继续保留原报告中的 P0/P1/P2 整改任务。后续维护按以下顺序执行：

1. 修改决策或契约前，先更新决策登记、history、registerVersion 和受影响文件的版本引用；
2. 修改 `index19.html` 时，同步审查并更新 `prototype-source-elements.json` 和追踪矩阵；
3. 修改任一 REST 契约后，运行 `pnpm openapi:bundle`，提交更新后的 `openapi.bundle.json`；
4. 合入前运行 `pnpm verify`，不得跳过 OpenAPI 3.1、引用完整性、bundle 新鲜度或负向测试；
5. 在后续功能报告中继续区分 planned contract、implemented code、deployed environment 和 release approval，避免扩大完成声明。
