# QA-09 A5 Replay生产关联补丁与测试部署前置

日期：2026-10-13。用户要求推进A2及无Active前置的A5可靠性缺口。

当前测试应用f8e943d2的Replay发送适配器不返回SQS MessageId，无法直接证明唯一Job→生产消息→实际消费。本补丁为SQS JSON adapter增加可选`sendWithReceipt`，保留原`send(): Promise<void>`，其他业务调用保持原契约。Replay sink传回真实SDK回执，Worker在成功发送后输出固定字段：Job、原messageId/seq、device/topic、实际SQS MessageId及请求ID。统一脱敏Logger负责日志写入，不输出Payload、凭据或任意异常。

元数据观测异常被隔离，不使成功发送重试、不改变sent/sendFailures或事务语义；缺实际回执不伪造生产证明。没有修改IAM/KMS、队列、内存、并发、pool或数据库Schema。

本地三个相关测试文件13项通过；AWS client构建、Ingestion类型检查及敏感sink检查通过，见[补丁检查](evidence/qa-09-a2-a5-2026-10-13/replay-patch-checks.json)。初始类型检查暴露共享发送端返回值与Quarantine接口不兼容，已改为新增可选方法，原失败日志保留为`replay-patch-checks-initial.json`。

本报告仅为补丁验证和部署前置，**目标生产关联仍NOT_RUN，A5及QA-09仍PARTIAL**。部署后应按同SHA CI/Deploy/Amplify与19工件重新绑定，一次波次合并Operator非空Replay、唯一生产/消费关联和自然日报后的同轮四表非空去重；不再尝试被拒绝的SSO直接SendMessage，不恢复性能测试。
