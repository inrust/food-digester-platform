## 交付结论

设备本地生成密钥与 CSR，项目 CA 签发同一叶证书用于 MQTT 与 Device REST mTLS；Onboarding 和 Rotate 返回公开叶证书及完整 CA chain，均不返回设备私钥。保持 RegisterCertificateWithoutCA、单设备 Policy/Thing 与 DEC-017 首 Heartbeat 完成首次接入。新增 Device ID CN/SAN、X509 元数据、公钥持久归属、双通道健康状态与受限轮换窗口。

轮换的新旧证书在各自有效期内并行，新证最长 24 小时完成合法 MQTT Heartbeat 与成功 REST Sync；任意顺序、重复或并发到达只提交一次撤旧证和管理员请求完成。撤销与 AWS 停用意图同事务提交，现有五分钟 Sweeper 每批最多 100 项重试 AWS INACTIVE；应用侧立刻拒绝已撤销旧证。到达截止仍未确认时应用拒绝新证，Sweeper 撤新证并保留旧证原状态/有效期。云端提交成功快照记录 REST 验证，不声明设备已收到网络响应。

决策登记：DEC-003@1.1.0、DEC-026@1.0.0；契约包 0.12.0 / 登记版本 1.36.0。

## 部署前置与迁移

以下是后续受控测试环境部署步骤，本次未执行：

1. 固件确认 Rotate 新 CSR 与 chain 契约，保留旧私钥直到确认成功；先做可恢复备份，暂停接入/轮换/Heartbeat/Sweeper 的写入，避免旧处理器与新迁移混跑。
2. 检查历史 CSR 公钥是否关联多个库存设备。新 `device_public_keys` 是永久所有权表；迁移对跨设备重复键失败关闭，必须人工核实实物、撤销相关证书并换新密钥后再迁移。不能用 `ON CONFLICT DO NOTHING` 隐藏冲突。
3. 应用 `20261001090000_csr_dual_channel_certificates`。迁移从 Onboarding CSR 回填归属，不伪造历史 MQTT/REST 验证；历史 ACTIVE 轮换新证从迁移时刻获得 24 小时窗口，旧证已 REVOKED 的已完成轮换保留完成状态。
4. 历史证书 PEM 可用于按需校验旧公钥；无法解析或没有旧公钥资料的设备拒绝 Rotate，需补登记真实公开证书。对历史云端生成的轮换键进行公钥归属核对/回填（由公开 PEM 导出 SPKI 指纹），避免迁移前遗留跨设备键复用。
5. 历史待领包若缺 certificateChain 或含 privateKey，不允许当前客户端领取；撤销未确认旧包证书并重签。已完成 Onboarding 的叶证不会自动换发为新的受控 Subject/SAN，需要正常 CSR 轮换。
6. 测试环境使用现有专用 CA。签发配置保留 `caCertificatePem` 与 CA 私钥；非自签签发 CA 另配置 `caCertificateChainPem`（上级至根，不重复签发 CA）。代码验证最多三张 CA、父签名、CA 属性、有效期与私钥匹配；REST Truststore 须覆盖完整信任链。不要读取或提交实际 CA 私钥/Secret 值。
7. 部署新代码和固件、恢复 Worker。核验返回 MQTT/REST URL、SNI、同叶证双通道、跨设备拒绝、旧证 AWS INACTIVE、清理失败重试与 24 小时超时。收集带代码 SHA、环境及时间的可重放回执。

迁移前重复归属查询（只读示例）：

```sql
SELECT request.public_key_fingerprint, COUNT(DISTINCT device.id) AS device_count
FROM onboarding_requests AS request
JOIN devices AS device ON device.serial_number = request.serial_number
```

## 未决风险与验收边界

- 目标环境迁移、CA/Truststore、MQTT SNI 与实际 REST mTLS、AWS 停用权限/调度均 **NOT RUN / NO RECEIPT**。完整本地 Gate PASS 不代表生产或目标 AWS ACCEPTED。
- AWS 签发/注册与数据库无法原子提交；已捕获异常登记 REVOKED 孤证并重试停用，但进程硬中断或清理记录也无法写入时仍可能留下 AWS 孤证。Onboarding 继续使用原持久 Job；同步 Rotate 此处仍需运维按 Thing/证书清单对账。未登记证书不能通过应用白名单，AWS Policy 侧风险需目标环境对账验收。
- AWS INACTIVE 异步重试有调度及服务故障延迟；每批 100 项。应用认证立即拒绝，Broker 连接可能在停用前存在。需监控 `iotDeactivationPending`、尝试次数、超时积压与调度错误。
- 24 小时保留旧证不延长其原有效期；旧证到期或撤销时不保证回退可用。新证响应丢失但服务器已提交时按一次交付语义返回 409，需运维恢复。
- 证书及 CA chain 是公开身份材料，仍禁止日志/审计记录完整包；RSA 私钥只在设备，CA 私钥仅由现有测试环境 Secret 签发器使用。
