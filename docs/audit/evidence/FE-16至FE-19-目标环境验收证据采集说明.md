# FE-16 至 FE-19 目标环境验收证据采集说明

## 1. 验收边界

本说明用于管理后台 FE-16～FE-19 的真实目标环境验收。`pnpm verify`、组件测试、Playwright 本地 mock、构建产物或 CDK synth 均不能替代本回执。未生成合规回执时，状态必须保持 `NOT RUN / NO RECEIPT`。

回执 JSON 遵循 `contracts/evidence/fe-16-19-admin-web-target.schema.json`，默认路径为 `docs/audit/evidence/fe-16-19-admin-web-target.json`。该文件是受控流水线工件，已被 Git 忽略，不得提交包含账号、令牌、联系人或其他敏感值的原始记录。

## 2. 前置条件

- 使用隔离测试账号/Stack，并记录 AWS account、region、Stack、管理后台 URL、API Base URL 和 Cognito User Pool ID。
- 部署记录必须给出 40 位 `sourceCommit` 与 40 位 `deploymentCommit`；环境实际部署值必须分别与之相等。
- 创建五个真实 Cognito 身份：PlatformSuperAdmin、PlatformOperator、Auditor、CustomerAdmin、CustomerViewer；Customer 角色绑定隔离 Customer。
- 使用真实 Chromium，禁用 Playwright route interception、Service Worker mock、代理 mock 和静态 fixture。
- 截图、HAR、CloudWatch 查询、审计记录等证据存入受控工件系统；回执只写不可变证据引用和去敏 requestId。

## 3. 必采探针

### 3.1 路由、身份与 API

- 五个页面：`/settings`、`/contracts`、`/contracts/new`、`/contracts/detail`、`/consumables`。
- 五角色分别以 Cognito token 登录；issuer 必须匹配本次 User Pool。
- 所有请求命中回执中的 `apiBaseUrl`，`mockedResponseCount=0`，至少记录 8 个服务端 requestId。

### 3.2 业务闭环

- FE-16：邀请无永久密码、角色整体替换、Customer scope、受控重置；自我提权为 403，最后一个 SuperAdmin 保护为 409，设置 `If-Match` 并发一成功一 409。
- FE-17：创建前字段校验、DRAFT 至少关联一台 eligible 设备、绑定/解绑、续约、终止；四个无 `contract:write` 角色均为 403；重复提交只产生一次 mutation。
- FE-18：unknown/stale 展示、联系人点击前零请求、点击后独立授权；列表无联系人字段；未授权为 403，跨 Customer 和不存在资源均为 404；PENDING→PROCESSING→COMPLETED/CANCELLED 且跳级为 409。
- FE-19：22 个生产路由均在 `zh-CN` 与 `en` 下检查；每种语言覆盖 375/768/1440px，页面级横向溢出计数为 0；刷新后语言保持；数字、百分比、日期和单位随 locale，日期时区不改变；协议枚举与业务数据保持原文。

### 3.3 隐私与清理

- 联系人未点击前：列表字段、请求次数、DOM、网络响应和应用日志泄露计数均为 0。
- 证据不得保存 Cognito token、Cookie、手机号、邮箱、临时密码或完整请求体；HAR 必须先脱敏。
- 删除测试用户、Contract、关联、耗材申请及测试配置，撤销临时权限，确认 `cleanup.completed=true`。

## 4. Gate 执行

将受控回执放到默认路径后，在与待发布源码相同的 checkout 执行：

```bash
pnpm check:admin-web-fe16-19-target-evidence
```

如回执由流水线保存在其他路径：

```bash
FDP_ADMIN_WEB_FE16_19_TARGET_RECEIPT=/absolute/path/to/receipt.json pnpm check:admin-web-fe16-19-target-evidence
```

以下任一情况均必须失败：缺回执、JSON/Schema 不合法、sourceCommit 与 HEAD 不一致、部署提交漂移、非隔离环境、非真实五角色、少路由/流程/locale/viewport、存在 mock、403/404/409 不符合、重复 mutation、联系人泄露、页面溢出或清理未完成。

## 5. 四层结论模板

| 层级 | 可声明条件 |
|---|---|
| module present | 源码、契约与组件测试存在 |
| app integrated | 正式组合根、生产 bundle 与本地全仓 Gate 通过 |
| browser verified | 本地 Chromium 业务/角色/双语多视口 E2E 通过；注明使用 mock |
| target integrated | 本独立 Gate 对绑定当前 HEAD 的真实目标回执 PASS |

仅前三层通过时不得声明 `target integrated` 或任务最终生产验收完成。
