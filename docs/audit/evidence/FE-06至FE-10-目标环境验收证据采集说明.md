# FE-06～FE-10 管理后台目标环境验收证据采集说明

## 1. 目的与边界

本说明用于在获授权、可清理的隔离 AWS 环境中验收 FE-06～FE-10。日常 `pnpm verify`、本地 Playwright mock、PGlite、OpenAPI 校验和 CDK synth 只证明仓库内交付，不能替代真实 Cognito、已部署 Admin API、浏览器和 Customer scope 回执。

目标环境 Gate：`pnpm check:admin-web-target-evidence`。默认读取 `docs/audit/evidence/fe-06-10-admin-web-target.json`，受控流水线也可通过 `FDP_ADMIN_WEB_TARGET_RECEIPT` 指定下载后的回执。仓库不提交占位 PASS 文件；缺失、格式错误、任一探针失败、未完成清理，或 `sourceCommit` 与当前 `git rev-parse HEAD` 不一致时必须失败关闭并保持 `NOT RUN / NO RECEIPT`。

## 2. 执行前提

- 部署产物和数据库 Migration 必须来自待验收的同一 40 位 Git SHA；回执的 `sourceCommit`、`environment.deployedSourceCommit` 与 Gate 执行时 HEAD 必须相同。
- 使用隔离账号、Region、Stack、User Pool、测试 Customer/Site/Device/License/Device User；禁止复用生产客户数据。
- 五种角色分别使用真实 Cognito 用户登录：PlatformSuperAdmin、PlatformOperator、Auditor、CustomerAdmin、CustomerViewer。
- 仅保存 Request ID、CloudWatch/X-Ray/流水线引用和脱敏摘要；不得写入 JWT、Cookie、密码、签名 URL、设备验证材料或业务原文。

## 3. 必验范围

1. 六个真实 Web 路由：`/devices/view`、`/devices/manage`、`/licenses`、`/configurations`、`/device-users`、`/alarms`。
2. 五个闭环：设备媒体与活动、生命周期/退役/Alias、历史 License 与合法动作、Configuration 与 Device User 同步阶段、Alarm URL 双向状态与 Critical 视觉。
3. 五角色菜单、直接 URL、读写按钮和 401/403/404 行为；Customer 角色跨租户详情及写操作必须返回 403 或 404。
4. 部署后 API 的成功与失败请求需保存 Request ID；危险动作双击只能产生一次业务变更，If-Match 并发必须一成功一 409。
5. DOM、网络响应与日志对密码、PHC、JWT、Cookie、签名 URL 的泄露计数均为 0。
6. 删除测试用户、Customer、Site、Device、License、配置、Device User、告警处置数据及临时资源，并保存清理证据。
