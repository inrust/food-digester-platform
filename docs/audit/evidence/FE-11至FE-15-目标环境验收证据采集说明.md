# FE-11 至 FE-15 管理后台目标环境验收证据采集说明

## 1. 目的与验收边界

本说明只用于获授权、可清理的隔离目标环境，验证 FE-11～FE-15 的已部署 Web、真实 Cognito 身份及已部署 Admin API。`pnpm verify`、本地 Vitest、PGlite、mock Playwright、OpenAPI 校验、构建与 CDK synth 均属于仓库内证据，不能替代本回执。

发布 Gate 为 `pnpm check:admin-web-fe11-15-target-evidence`，默认读取 `docs/audit/evidence/fe-11-15-admin-web-target.json`；受控流水线可通过 `FDP_ADMIN_WEB_FE11_15_TARGET_RECEIPT` 指定下载后的回执。回执结构由 [fe-11-15-admin-web-target.schema.json](../../../contracts/evidence/fe-11-15-admin-web-target.schema.json) 锁定。

仓库不提交示例 PASS 或占位回执。文件缺失、格式不合法、探针失败、提交不一致或清理未完成时，Gate 必须非零退出，状态保持 **NOT RUN / NO RECEIPT**。该 Gate 是发布/严格验收的显式步骤，不并入普通本地 `pnpm verify`。

## 2. 执行前提

- `sourceCommit` 是待验收应用源码的 40 位小写 Git SHA；`deploymentCommit` 是部署/IaC 输入的 40 位小写 Git SHA。目标环境必须分别回报 `deployedSourceCommit` 与 `deployedDeploymentCommit`，且逐一相等。
- 使用隔离 Account、Region、Stack、User Pool、Customer、Site、Device、License、固件包及媒体对象；禁止复用生产客户数据。
- PlatformSuperAdmin、PlatformOperator、Auditor、CustomerAdmin、CustomerViewer 分别由真实 Cognito 用户登录，Token issuer 必须匹配回执中的 User Pool。
- 浏览器不得注册 route interception、HAR replay、service worker mock 或静态 API fixture；`mockedResponseCount` 必须为 0。
- 仅保存 Request ID、CloudWatch/X-Ray/流水线引用与脱敏摘要。JWT、Cookie、密码、Token、签名 URL、固件签名材料及业务原文不得进入回执。

## 3. 必验范围

1. 七个已部署路由：`/esg/overview`、`/esg/devices`、`/devices/operate`、`/ota/packages`、`/ota/campaigns`、`/media`、`/audit-logs`。
2. FE-11：跨两页 ESG 数据聚合与同筛选导出；用户时区及 DST 边界；API Request ID 可追踪。
3. FE-12：普通与危险命令、确认失败、越权 403、重复提交只产生一次变更、`PUBLISH_FAILED` 可见；温度阈值只走 Configuration。
4. FE-13：固件上传/完成校验、灰度 Campaign、暂停/扩批/失败重试；失败码与脱敏原因可见，原始凭证泄露为 0。
5. FE-14：跨 Customer 请求返回 403/404；短链过期返回 403/410、重新签发可用，持久化签名 URL 数量为 0。
6. FE-15：仅 PlatformSuperAdmin/Auditor 可读；PlatformOperator、CustomerAdmin、CustomerViewer 均被拒绝；浏览器写请求数为 0；DOM/网络/日志敏感信息泄露为 0。
7. 删除测试身份、业务数据、S3 对象、固件、媒体及故障注入，回执 `cleanup.completed=true`。

## 5. 执行与归档

1. 部署精确 `sourceCommit` 与 `deploymentCommit`，在隔离环境执行全部探针。
2. 将回执保存于流水线受控工件；需要严格验收时通过环境变量指向下载后的文件。
3. 在待发布源码提交上执行 `pnpm check:admin-web-fe11-15-target-evidence`。
4. Gate 通过只证明该回执绑定的提交与目标环境；任一提交或部署变化后必须重新采集。
