## 一、任务完成概况

### 1.1 结论

FE-11～FE-15 均存在较完整的页面组件、API adapter、纯逻辑和 jsdom 测试，但五项任务均未进入当前浏览器应用组合根。路由可被识别、菜单可见，实际访问时却统一进入“该页面尚未接入当前管理后台组合根”的占位分支。版本化交付清单及交付 Gate 仍固定为 FE-01～FE-10，现有 Playwright 8 项也只证明 FE-01～FE-10 的浏览器路径，因此形成了“交付 Gate 通过、五个任务实际不可用”的假绿。

按任务清单 §3.1 完成定义及每项验收基准，五项任务均判定为 **FAIL**，严格实际完成率为 **0/5（0%）**。

### 1.2 完成率口径

本报告不采用代码行数或文件存在率。任务只有同时满足下列条件才计为 PASS：

1. 规格、依赖契约和冻结决策一致；
2. 页面组件与 API adapter 已进入浏览器组合根，生产路由可执行业务闭环；
3. lint、typecheck、相关单元/契约测试及构建通过；
4. 任务列出的权限、负向路径、分页、时区、危险确认和错误态由确定性测试证明；
5. 核心路径由真实 Chromium E2E 证明，而不是只渲染孤立组件；
6. 若声明目标环境完成，还须有绑定精确提交、真实 Cognito 与已部署 API 的回执。

计算公式：`实际完成率 = PASS 任务数 / 5 × 100%`。`CONDITIONAL` 与 `FAIL` 均不计入完成数。

### 2.2 需求逐项核对摘要

#### FE-11

- 两个页面组件覆盖规格列出的指标、单位、完整率、计算版本、日/周/月切换、筛选、免责声明与导出过期提示，孤立组件测试通过。
- `/esg/overview` 与 `/esg/devices` 已注册路由，但 `AdminWebApp` 没有对应 switch 分支，浏览器实测两个页面标识均不存在。
- REST 列表是游标分页；页面仅对传入的当前 rows 做周/月聚合，既没有“加载更多”控件，也没有组合层收集全部页。跨页时图表/表格会少算，而导出由服务端按完整筛选快照生成，不能保证“导出筛选与页面一致”的数据范围语义。
- `zonedDateRangeToUtc` 用某日午夜偏移加固定 24 小时计算尾日，DST 切换日会多/少一小时；`2026-02-31` 也会被静默归一为 `2026-03-03`，与“非法输入应提示”不符。

#### FE-12

- 22 个 CT-04 命令、快捷动作、高风险确认、设备状态门、ACK/attempt 时间线和活动导出已有组件级覆盖。
- `/devices/operate` 浏览器实测只显示占位页，没有设备加载、命令查询/创建、详情轮询、活动导出和 Media 回源的组合逻辑。
- 后端/OpenAPI 的正式 `CommandStatus` 包含 `PUBLISH_FAILED`，前端类型、筛选选项和状态文案均遗漏该值。真实响应到达时状态列/详情文案为空，也无法筛选发布失败命令。
- 任务要求 M/N 与温度阈值走 Configuration；页面虽提供 Configuration 跳转，但通用命令下拉仍包含并可提交 `SET_TARGET_TEMPERATURE`。现有测试只验证跳转按钮不发命令，没有负向阻断通用下拉路径。

#### FE-13

- 包校验、首批一台、扩批禁默认全选、动作状态矩阵和最终全量确认等局部逻辑较完整。
- `/ota/campaigns`、`/ota/packages` 浏览器实测均为占位页，S3 直传 callback、包列表、Campaign/target 加载和动作回源未被组合。
- 规格明确要求“失败原因按设备展示”，但 `OtaTargetView` 契约不含 failure reason/error 字段，页面只显示状态并提示需去告警/事件页追溯。该项不是前端可单独关闭的问题，需先演进 BE-OTA 契约和实现。

#### FE-14

- `MediaPreview` 对 AVAILABLE/DELETED、IMAGE/VIDEO、未知类型、过期 URL 和重新申请已有组件测试，授权 URL 仅保存在组件状态。
- `/media` 浏览器实测为占位页；因此元数据筛选、跨租户错误、实时重签和未知类型降级均没有真实路由证据。
- 时间筛选通过 `new Date(datetime-local)` 使用浏览器系统时区，而不是用户在后台壳层选择的展示时区；也没有校验 `from <= to`。跨时区使用或倒置区间会产生错误查询或依赖后端 400 兜底。

#### FE-15

- 页面和 API adapter 保持只读，前后值按敏感字段名再次脱敏，孤立组件测试通过。
- `/audit-logs` 浏览器实测为占位页；当前页面无法实际查询审计记录。
- 任务清单写明“Customer 角色仅自身”，而 DEC-012/AUTH-01 与 `admin-audit-api.json` 只给 PlatformSuperAdmin/Auditor `audit:read`，前端路由也排除了 Customer 角色。当前文档以契约覆盖任务要求，但没有同步修改任务清单或形成版本化偏差决策，验收源之间仍冲突。
- `AuditLogsPage.tsx` 导入未使用的 `AuditLogView`，定向 ESLint 与全仓 `pnpm verify` 均失败。

### 3.6 风险归纳

1. **发布风险最高**：应用可展示菜单和面包屑，却只返回占位页；现有 Gate 又不会失败，属于用户可见的静默缺交付。
2. **设备控制风险高**：FE-12 同时存在状态枚举漂移与配置边界绕行，既会丢失失败可见性，也可能走错控制通道。
3. **报表可信度风险高**：FE-11 的分页聚合和 DST 处理会使页面数值、日期边界与导出结果不一致。
4. **契约治理风险高**：FE-13 失败原因及 FE-15 Customer 审计可见性都不是单改 UI 能关闭，必须先同步任务、决策、OpenAPI、DTO、后端和测试。
5. **证据风险持续存在**：绿色单测、构建、现有交付 Gate 和现有 E2E 均不覆盖本次五项正式路由；目标环境也无回执。

## 四、整改建议

### 4.1 P0：恢复可运行交付与失败关闭

1. 为 FE-11～15 新增真实 controllers，负责首屏加载、游标分页、筛选回源、导出/轮询、详情、错误态、角色与用户时区注入；在 `AdminWebApp` 为 7 个 pageState 添加显式分支，并加入 `IMPLEMENTED_PAGE_STATES`。
2. 将版本化交付清单升级到至少 FE-01～15，逐项登记任务、7 个路由、controller、稳定 testid 与本次实际需要的 OpenAPI operationId。
3. 扩展 `check-admin-web-delivery.mjs`：要求 FE-11～15、7 路由、controllers、页面标识和 operationId；添加负向测试，删除任一任务/route/controller/testid/operation 时必须失败。
4. 新增 Playwright 核心路径：ESG 两页与导出、Command 创建到终态、OTA 上传/Campaign、Media 续签、Audit 只读详情；覆盖五角色、403/404、空态、分页、时区、409/重复提交、短链过期和 375/768/1440 视口。
5. 删除 FE-15 未使用导入，并先保证定向 ESLint、全仓 lint 通过；范围外 FE-18 lint 问题需由其任务单独关闭，不能忽略或归入本报告整改完成。

### 4.2 P1：关闭业务与契约缺陷

1. FE-11 在 controller 中按筛选收集完整游标范围后再聚合，或新增服务端周/月聚合契约；页面显示的数据范围必须与导出快照一致，并测试跨两页边界。
2. 用可靠的时区库/Temporal 语义计算“下一日当地午夜减 1ms”，严格校验真实日历日期；补 America/New_York 春秋 DST 和 2 月非法日期负向测试。
3. FE-12 从 OpenAPI/共享 schema 生成或 parity 锁定全部 Command 状态，补 `PUBLISH_FAILED` 类型、文案、筛选与 E2E；将 `SET_TARGET_TEMPERATURE` 从可提交集合排除或先完成版本化需求决策，保证温度阈值只走 Configuration。
4. FE-13 先演进 OTA target 契约，增加结构化失败码/脱敏失败原因，再同步数据库/领域服务、OpenAPI、前端 DTO、页面和测试；不要用告警页跳转替代明确验收项。
5. FE-15 由产品/架构明确选择：若维持 DEC-012 禁止 Customer，则同步修订任务清单和验收基准；若保留任务清单要求，则版本化升级权限矩阵、OpenAPI、服务端隔离、前端路由和五角色测试。不得仅以开发文档单方面覆盖规格。
6. FE-14/15 统一复用用户时区转换工具，增加 `from <= to` 字段级校验和跨时区浏览器测试。

### 4.3 P2：修正文档与目标环境证据治理

1. 重写五份开发文档的当前状态，按 `module present / app integrated / browser verified / target integrated` 四层陈述；移除过时 Gate 故障和未限定的 `✅` 完成声明。
2. 建立 FE-11～15 目标环境回执 schema、采集说明与失败关闭 Gate；回执至少绑定 40 位 source commit、部署 commit、隔离环境、真实 Cognito 五角色、7 路由、零 mock、API requestId、跨 Customer 拒绝、短链/危险操作/只读与敏感信息泄露为 0、清理完成。
3. 目标 Gate 不应默认纳入普通本地 `verify` 后用占位 PASS 文件绕过；发布验收流水线应显式执行，缺失回执必须保持 `NOT RUN / NO RECEIPT`。
