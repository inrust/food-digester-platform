## 变更与观测语义

| 阶段 | 含义及边界 |
| --- | --- |
| admin-authenticate | 独立JWT/JWKS验证总耗时；不记录Token、claims或认证失败消息 |
| db-transaction-open | 根事务调用至回调开始，包含连接获取、适配器/事务开启和BEGIN；不是纯连接池等待 |
| db-transaction-callback | 业务读取/条件更新及成功审计的事务回调；含SQL等待，不能等同CPU耗时 |
| db-transaction-finish | 回调离开至根事务承诺完成；含提交或回滚及适配器开销，FAIL表示事务承诺拒绝，不能等同回滚失败 |
| db-transaction | 根事务总耗时；只在合同PATCH显式启用，不改变其他审计写接口或嵌套事务语义 |
| contract-load / contract-version-update / contract-readback | 分开当前行读取、版本条件更新（含VERSION_CONFLICT抛出）、成功后读回；未新增SQL、锁或重试 |
| audit-success-write / audit-failure-write | 成功审计仍在业务事务内，失败审计仍独立写入；后者包含连接获取；失败审计失败不能掩盖原业务异常 |
| audit-list-query / audit-detail-query / audit-view | 审计查询总耗时（含连接获取）与返回视图转换分开；401/403不运行查询，查询无匹配404不冒充数据库异常 |

日志均绑定Gateway请求ID、Lambda invocation ID、operation、开始/完成时间和安全错误码；仅扩充允许码VERSION_CONFLICT，不记录SQL、参数、合同名称/联系方式/原因、审计前后值或任意异常消息。手动阶段完成函数幂等，发射器失败不改变业务返回和重试；根事务只有一次开启，嵌套复用不伪造独立提交。

执行器`qa09-http-observation.mjs`为每次API请求在发送前写入独立UUID，保留原指定PATCH UUID。失败分别记录AWAIT_HEADERS或READ_BODY、响应头是否收到、HTTP状态/Gateway ID（可得时）、完成时间及受限错误类别；正文解析/传输失败不得形成完整成功回执，不自动重试写请求，不把Token/正文保存到传输账本。合同审计详情每条做三次独立GET采样，不是失败重试；任一失败仍使专项FAIL，失败样本与后续样本都保留。
