# QA-09 IAM 真实拒绝根因复核

根因已确认：FDP-InfraSetup 的 AwsSSOInlinePolicy 包含 iam:PutRolePolicy，但允许语句的 iam:PermissionsBoundary 条件要求 FDP-PermissionsBoundary；目标 Worker 实际绑定 FDP-ServiceBoundary。因此目标角色不满足身份策略的 Allow 条件，真实请求为 IMPLICIT_DENY。此前“SSO没有PutRolePolicy权限”的表述不准确，应改为“包含操作授权，但目标Boundary条件不匹配，导致该请求无有效Allow”。

## 真实请求证据

原写入拒绝时间 UTC 2026-10-02 10:45:39，CloudTrail EventId `ed9b6b84-ce7d-4a04-8b52-40ec29b49714`，AuthorizationId `bv2653fif43g3n4sqy0teytt2`。通过 AWS IAM Toolbox GetRequestAuthorizationDetails 获取原请求判定，操作为 iam:PutRolePolicy、目标为唯一批准Worker、判定IMPLICIT_DENY，真实请求上下文 iam:PermissionsBoundary 为 `arn:aws:iam::065986019555:policy/FDP-ServiceBoundary`。不是依据模拟猜测实际请求条件。

新只读GetRole请求同样IMPLICIT_DENY，AuthorizationId `4qfufo9l6lodk8555flyphs00`，实际Boundary上下文一致。当前SSO角色自身无Permissions Boundary，附加PowerUserAccess及AwsSSOInlinePolicy。原请求评估列出身份策略和Session Policy；最终报错为无身份策略允许，条件匹配失败已足以解释该拒绝，未发现需要改SCP或目标角色Boundary的证据。

## 条件对照模拟

| iam:PermissionsBoundary 输入 | PutRolePolicy | GetRole |
| --- | --- | --- |
| 省略 | allowed | allowed |
| 实际 FDP-ServiceBoundary | implicitDeny | implicitDeny |
| 策略要求 FDP-PermissionsBoundary | allowed | allowed |

StringEqualsIfExists 仅在条件键不存在时跳过匹配；真实请求中键存在且值不同，条件为false。首次模拟省略该键，造成allowed假象，其missingContext为空也不证明真实条件被完整重放。带入实际值的模拟报告另有iam:AWSServiceName及iam:PassedToService缺失提示，不能声称模拟无missingContext；原真实请求的Toolbox判定才是实际拒绝证据。
