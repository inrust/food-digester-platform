### 1.1 判定口径

为避免把“已有文档/测试”误报为“协议已冻结并可交付”，本次使用三组互不替代的指标：

1. **门禁闭环率**：决策登记达到 `frozen`、版本不低于 `1.0.0`、批准人与批准时间齐全；
2. **工程契约覆盖率**：存在版本化策略/Schema、类型或查询模块、负向测试、决策版本追溯；
3. **严格端到端验收率**：同时满足门禁闭环、需求一致、生产消费一致、专项测试和全仓 `verify` 通过。

未冻结的暂定策略只算工程准备，不算协议完成；专项契约测试通过也不能抵消生产实现或全仓验收失败。

### 1.2 严重度口径

| 级别 | 判定标准 |
|---|---|
| 阻塞级 | 协议门禁无法关闭、关键验收失败，或会使设备/云端无法按冻结契约互操作 |
| 高危 | 可能造成密钥材料交付失败、授权/业务语义错误，或冻结变更无法可靠传导到实现 |
| 中危 | 降低审计可复现性、需求追溯性或质量门禁可信度，但短期不直接破坏核心数据 |
| 低危 | 文案、状态说明或维护性偏差，当前影响较小但会误导后续开发/复核 |

## 5. 整改建议

### 5.1 P0：关闭阻塞项后才允许重新评审 Gate

1. **冻结或明确否决 10 个 pending 决策。**
   - 含待定参数：DEC-001、002、005、008、010，应补齐业务值、批准人、批准时间和迁移影响；
   - 当前无待定参数：DEC-006、007、009、011、012，应尽快执行正式批准或退回修改，不应长期保持 `pending`；
   - 每项冻结后提升登记与策略版本至 `>=1.0.0`，生成变更记录并同步所有 `x-decision-versions`。

2. **修复 DEC-004 端到端线协议。**
   - 实现固定参数的生产 Argon2id adapter；
   - 内部材料编码为 `$argon2id$v=19$m=32768,t=3,p=1$...$...`；
   - Sync 的 Device User 输出改为 OpenAPI 定义的 `userId/username/displayName/passwordHash/status`；
   - 清理旧 `verifier` DTO；补充固定测试向量、PHC 解析负向测试、日志/审计泄漏测试和最低配置设备性能收据；
   - 使当前失败的 Device Sync 契约测试转绿。

3. **重构 DEC-003 领取交付状态机。**
   - 明确 `PREPARED → DELIVERY_RESERVED → DELIVERED/UNCERTAIN → CONFIRMED/REVOKED` 等可恢复状态；
   - 不在无法确认 HTTP 交付结果前静默丢弃唯一密文；若响应提交或连接状态不确定，则下一次请求必须确定性触发“吊销未确认证书并重签”，不得永久返回 PENDING；
   - Onboarding 与 Rotate 使用同一交付语义；补充响应中断、超时、重复领取、并发领取、过期、重签和首次 Heartbeat 清理测试。

4. **让协议门禁真正阻断发布。**
   - `check-decisions` 保留“可在开发分支列出 pending”的模式，同时新增发布/联合验收模式：只要目标任务依赖 pending 决策即非零退出；
   - pending 决策派生的 Schema 必须标记 draft，禁止进入发布包或生产 Ingestion；
   - 建立“目标任务 → 决策状态 → 契约版本”的自动 Gate，而不是只打印未决列表。

### 5.2 P1：消除策略与实现漂移

1. **统一消费路径。** 生产代码直接从 `@fdp/contracts/...` 导入策略查询，或由生成器产出共享常量；禁止在 apps/packages 复制 provisional 值。
