## 1. 任务完成概况（整改前基线）

### 1.1 判定口径

本报告将“有源码”、“本地测试通过”、“生产组合根已接线”和“目标 AWS 环境验收通过”视为不同层级。单项任务只有在需求行为、契约/持久化、负向路径、生产接线及需要的目标环境证据全部闭环时才计为 `PASS`。

- `PASS`：全部验收条件有当前证据，无阻断/高危未闭环项。
- `CONDITIONAL`：局部实现和测试成立，但生产接线或验收证据未闭环。
- `FAIL`：核心路径不可达、上游决策使成功路径必然失败，或已复现会改变业务结果的缺陷。

### 3.5 风险联动

1. B-03 使 BE-OTA-01 的真实成功路径不存在，因而 BE-OTA-02/03 的大量绿色测试仅能在 mock `VERIFIED` 包上成立。
2. B-01/B-02 与 L-01 叠加，使“OpenAPI 正确 + 全量 verify 通过”与“用户可调用”出现实质性断层。
3. H-03/H-04 使 OTA 在多 Lambda 实例下同时存在重复执行和丢失审计两种相反风险；仅靠稳定 `meta.id` 不能修复服务端副作用。
4. H-01 在高风险命令上与 M-03 叠加，会同时削弱首次授权和重试边界。

## 4. 整改建议

### P0：恢复可交付路径

1. 冻结 OTA 签名决策：登记唯一 DEC，确定算法、信任根、编码和规范载荷，更新策略为 `frozen >= 1.0.0`，提供固定测试向量和真实 verifier adapter。
2. 将 Command 创建/查询、Firmware Package、OTA Campaign 的 operation 加入已交付清单、`AdminOnboardingRouteSet`、路由映射和 Lambda 组合根，装配 S3/验签等 adapter 与所需 IAM。
3. 为 Command Publisher、Command Timeout、OTA Dispatcher 建立独立 runtime entry 和 EventBridge/SQS 触发，接入 IoT Data Plane/S3，明确最小权限、重试、DLQ、告警和冷启动失败策略。
4. 拆分 Command 的“发布失败”和“设备执行失败”：优先使用 attempt outcome/delivery state，仅允许明确的传输失败重试；ACK 终态 `FAILED` 必须不可发布。添加本报告 H-01 负向回归。

### P1：关闭安全与并发问题

1. OTA 下载改为真正的 target-bound 授权：可使用一次性下载令牌/受鉴权代理，服务端校验 `deviceId + otaTargetId + packageId + expiry + unused/revoked`；不得把普通 S3 bearer URL 当作设备绑定证明。
2. 为 OTA target 增加条件 claim + lease token；发布前再校验 Campaign/target/package/device；终态写入验证 lease 所有权，同时覆盖暂停/取消竞态和过期 lease 恢复。
3. 将 target 状态、OTA_AVAILABLE 通知 Outbox 和 DEC-016 publication Outbox 收敛到同一数据库事务，并为 Outbox 设置可验证的幂等键。
4. 扩展 `CommandAttempt` 为 `outcome/errorCode/providerMessageId/finishedAt`，发布状态转移必须审计；查询时间线展示真实成败。

### P2：对齐语义与治理

1. 将“默认禁止一次全量强制升级”拆成明确的单批限制/需审批的最终扩批，允许在灰度验证后安全覆盖最后一批；不要无条件拒绝累计全覆盖。
2. 冻结高风险 Command 确认语义：明确是重新认证、MFA、双人审批还是仅 UI 确认；契约、实现和审计按同一决策执行。
3. 新增 CMD/OTA 生产接线 Gate：契约 operation 与 delivered operation 双向覆盖，三个定时/事件 Worker 及 IAM/S3/IoT 资源完整性，签名策略冻结，且缺任一项失败关闭。
4. 修正“已落地”和待冻结异常的追溯文案，明确区分 core module、production wired 和 target verified。

### 目标 AWS 验收与退出条件

完成 P0/P1 后，必须在隔离 AWS 环境产生与精确 Git commit 绑定的回执，至少包含：

- Admin Cognito 认证、五角色权限矩阵、跨 Customer 拒绝，以及全部 CMD/OTA REST operation 的成功+负向响应。
- 真实 IoT Data Plane Topic/QoS/Payload，Retired/过期命令不发布，发布重试不生成新 commandId，ACK 成功/失败/未知/冲突/迟到路径。
- 真实 S3 上传完成、Hash/签名/型号错配拒绝、不可覆盖，以及受目标设备绑定的下载授权和 15 分钟过期后拒绝。
- 首批 1 台→分批扩容→暂停/恢复/取消/重试的真实调度，包含并发 dispatcher 和取消竞态探针。
- DEC-015 唯一 ACK 通道、非目标设备拒绝、状态幂等，以及 DEC-016 publication/result 记录和清理回执。

只有上述回执 Gate 通过、B/H 项全部关闭、六项任务重跑本报告的定向负向探针后，才能将完成率从 0% 调整为已验收。
