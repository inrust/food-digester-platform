# QA-09 A2 设备验签与 A5 可靠性推进

本记录承接[A1 冻结清单](QA-09-久拖根因与最短验收任务清单-2026-10-13.md)。只执行无 Active 前置的 A5 缺口，保留 A2、自然生命周期及 OTA 的真实业务校验；本地工具通过不代表设备 VERIFIED 或 QA-09 ACCEPTED。

**当前结论：A2 为 BLOCKED_EXTERNAL_OPERATIONS_AUTHORITY，由运营提供受控验签/签名通道；A5 本轮关闭 3 个冻结补验项，全部自有资源清理和独立读回通过。QA-09 仍为 PARTIAL，全部 A5 尚未验收。**


## A2：已落实工具，目标验证仍受权限前置阻断

- 新增独立 DEC-020 设备模拟验签器。生产代码不导入云端签名函数，按实际 UTC 全时间戳、排序后的 OTA/REMOTE_CONTROL 等线协议权限重建签名原文；拒绝异设备/客户、失效许可证、撤销状态、非当前输入、额外字段及签名变化。通过后只返回 SHA256 和版本、设备、证书、ETag、nonce 绑定，不输出 HMAC 密钥或完整签名。
- 新增受控 worker：仅接受自有前缀、冻结代码摘要、当前应用版本、五分钟内有效输入和专用测试执行角色。密钥只在受控执行环境内部读取和使用，输出不能作为已完成 Sync 确认或真实设备证明。
- 新增 DEC-022 OTA 协议夹具：绑定固定测试 OTA Key、确切文件字节及 model/version/packageType/sha256 原文，要求真实 KMS 签名并独立验证公钥签名。夹具明确非可刷写物理固件，只用于云端协议业务验收。
- 当前 `fdp-test-migration-runner-role` 只允许读取 RDS Secret；没有许可证 Secret 的 GetSecretValue。OTA Key Policy 仅有管理和 API Verify，没有 Sign 授权。数据 Key 通过区域 SecretsManager 委派解密，但仍需执行角色的精确 Secret/Decrypt 权限。公开记录仅保留[脱敏权限结论](evidence/qa-09-a2-a5-2026-10-13/a2-permission-summary.json)，完整只读权限证据按用户要求留在本地。未读取 SecretString，未尝试越权 Sign。
- 已在本地准备具体最小权限提案分离许可证 verifier 与固件 signer，列出专用角色、信任策略、精确 IAM 策略及 OTA Key Policy **增量**语句。提案为 `PROPOSED_NOT_APPLIED`，不是现有资源或部署证明。2026-10-13 用户明确说明本人无此权限，由运营人员授权并操作。优先复用已有受控验签/签名服务；两个专用角色只是可选实施方案，不能把新增角色作为业务验收目标。本次测试部署授权不包含 IAM/KMS。若新增临时授权，业务终态后应移除并读回确认。完整待签名文件、权限增量、所需回执与撤权步骤已整理为本地运营交接单，未向运营发送消息。

A2 余下必需步骤：落实受控 verifier/signer → 对同轮真实 mTLS Sync 许可证独立验签 → 使用真实设备认证确认 Sync 并读回 VERIFIED → 完成可信固件上传、Campaign、设备结果及审计。现有固件目录无可复用包；104 字节非可刷写协议夹具和 DEC-022 精确原文已准备，状态为 PREPARED_UNSIGNED_NOT_TARGET_VERIFIED。当前没有真实目标验签/签名回执，A2 保持 BLOCKED_EXTERNAL_OPERATIONS_AUTHORITY。物理刷写/耐久属于发布阶段验收，云端验签和 OTA 业务不能延后替代。

## A5：本轮执行范围

1. 同一自有波次通过真实 MQTT 产生 30 条 receipt、小时数据和归档；等既有自然 Summary 为所选 Replay 设备生成非空日汇总。只读业务 API 有界等待，不手工调用共享 Summary，不向数据库插入汇总。
2. 新建 SUPPRESS 的自有 PlatformOperator 并真实 SRP 登录；以该身份提交恰好一个自有已归档 telemetry 的 Replay，核对服务端 requestedBy、非空扫描/发送与终态及审计。
3. 通过已部署 Replay 的生产日志绑定唯一 Job → 原始 messageId/seq → 实际 SQS MessageId，再关联同一消息的 ROOT_TRANSACTION_COMPLETED、DUPLICATE_SKIPPED 和最终 PROCESSED。直接 SSO SendMessage 尝试为零。
4. 保留原 dedup Gate：同轮 receipt/hourly/daily/ARCHIVE outbox 四表都必须非空，完整行摘要及原始范围外摘要前后完全相同。空表、混用独立 ESG 波次、缺消费关联均不能 PASS。
5. Replay 与对应 Ingress 消费均取得精确终态后禁用并读回 Operator 的 DISABLED 墓碑，删除其 Cognito 身份；清理 Replay 和全部自有资源，再独立读回数据库空夹具、两个 Cognito 身份、归档版本及所有精确 Build 终态。任何未知写入先冻结清理，不盲重试。

本轮结果仅能关闭上述指定可靠性缺口。其余 MQTT 类型、坏消息隔离/批次部分失败、归档队列及自然调度关联仍单列为 A5 必需项，不能以本轮 PASS 冒充全部 A5 或 QA-09。

剩余 A5 的最小证据和执行约束已整理为[后续必需项清单](evidence/qa-09-a2-a5-2026-10-13/a5-remaining-execution-plan.json)：先确定自有坏消息的受控执行与精确清理路径，再做故障探针；队列与自然调度必须取得唯一关联，配置或时间接近不能替代。此清单为准备记录，没有新增云端故障注入，也没有把必需项改成发布延期。

## 执行器身份标识核对

等待期间源码核对发现，冻结执行器 `43a6f196` 把 Replay 的 `requestedBy` 与业务数据库 `userId` 比较；实际认证模块使用经过签名验证的 Cognito `sub` 作为 actorId，两者可以不同。这是执行器的标识比较错误，不能修改业务记录来迎合错误判定。

新增独立只读身份映射器，准备在同轮 Operator 真实 SRP 登录后读取其 Cognito subject/状态/唯一角色，并绑定原始 seed、Build、应用版本和文件摘要。原始运行结果保留；后续汇总仅在同轮 Job 的 requestedBy 与该真实 subject 一致、Replay/生产/消费/四表去重/审计/清理全部通过时，才能纠正这一项比较。若映射或任一业务证明缺失，不能关闭缺口。不会为此再创建 Replay 或重做全量波次。

目标执行又定位到一处工具契约错误：停用 Operator 已返回 200，随后执行器调用契约不存在的 `GET /admin/users/{id}`，收到 404 并正确冻结清理。已改为正式列表接口按邮箱和 DISABLED 筛选读回。原 FAIL、404 和清理冻结记录不改写；恢复入口先复核同一 Job/精确消费/四表去重均终止、全部 Build 成功，再通过真实登录和正式列表确认停用，不重提停用或 Replay，仅清理自有身份、业务夹具、证书/设备/客户及对象版本。恢复和独立最终读回未完成前，不关闭三个 A5 缺口。

首次恢复的业务清理因 `BUSINESS_BASELINE_DRIFT` 拒绝并回滚，精确 Build `68c3c3e1-7a8f-47b7-99d6-fa77597d3035` 已终止为 FAILED。只读差异核验显示仅 outbox 从 64 条增为 65 条，新增恰为本轮 Operator 停用生成的 `COGNITO_ADMIN_RECONCILIATION`，状态 PUBLISHED；其他业务表摘要完全一致。原清理范围未纳入自有用户停用事件。修复仅在数据库读回用户 ID/邮箱/Cognito subject、DISABLED 和唯一 PlatformOperator 角色一致时，将其已完成 DISABLE 事件纳入自有清理；用户墓碑保留，其他事件及范围外摘要继续严格比较。真实 SQL 负向测试覆盖 ACTIVE、错误 subject、未完成事件及外部数据漂移。恢复使用新回执，不重启旧失败 Build。
