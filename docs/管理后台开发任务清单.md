# 管理后台开发任务清单

## 1. 文档目的

本文根据以下两份文档的全部内容整理，只保留与管理后台以及 API 接口开发相关工作，并将其拆分为可执行的开发步骤：

- 《AWS 云端方案关键问题与解决方案》；
- 《AWS 云端业务与管理后台开发实施方案》。

同时参考《Device-Cloud Communication Design 解析与信息汇编》定位页码、字段和待确认项；该解析文档是检索与复核辅助，协议事实仍须回溯原始 PDF，不提升或替代原始文档的优先级。

同时以客户提供的 `index19.html` 作为管理后台的信息架构、页面布局、字段和交互意图参考。该原型是静态演示，不是设备协议、权限模型或后端数据模型的事实源。

本文只保留接口开发、云端业务后端、设备消息处理、管理后台后端、管理后台前端、开发所需基础设施代码、自动化测试和现有 AWS 测试环境的软件验收。运维、值守、生产发布、容量治理和成本治理任务已剥离。

需求解释优先级固定为：①《Device-Cloud Communication Design》；②两份 AWS 云端方案；③`index19.html`。原型与前两级冲突时必须修正原型实现，不能反向修改协议或弱化安全约束；原型新增但上级资料未定义的能力必须进入决策门禁，不能直接假设设备端已支持。

## 2. 开发范围边界

### 2.1 保留的开发工作

- MQTT Topic、Payload、QoS 适配、JSON Schema 和错误码；
- REST OpenAPI、统一响应、分页、并发控制和幂等契约；
- 数据库 ERD、Schema、Migration、约束和业务状态机；
- AWS IoT、SQS、Lambda、RDS、S3、Cognito、API Gateway 等应用依赖的 CDK 定义；
- Onboarding、证书、Sync、Deactivate、Media 等设备接口；
- IoT 消息接收、校验、幂等、隔离、归档、聚合和重放；
- Customer、Site、Device、License、Configuration、Device User 等管理后台后端；
- Contract、Consumable、Alarm、ESG、Command、OTA、Media、审计和导出功能；
- 管理后台全部页面及其 API 对接；
- 设备模拟器、单元测试、契约测试、集成测试、端到端测试和安全测试；
- 在现有 AWS 测试环境执行上述软件验收、自动清理测试数据并归档可复核回执。

### 2.2 明确剥离的运维工作

以下内容不生成开发任务，也不得作为本清单完成条件：

- CloudWatch 运维仪表盘、AWS 资源告警、队列堆积告警和基础设施值守通知；
- 生产环境日常巡检、日志巡检、证书到期人工处置和 DLQ 人工处置；
- RDS 备份策略、PITR 操作、快照管理、恢复演练、跨区域备份和灾备切换；
- Multi-AZ、只读副本、生产升配、自动扩缩容和 ECS Fargate 迁移；
- WAF 运营、IAM Identity Center 运维、账号治理和人工访问审批；
- AWS Budget、成本异常告警、Pricing Calculator 复核和月度成本治理；
- Runbook、值班表、联系人升级机制、事故响应和长期 7×24 运维；
- 生产 Canary 发布、人工环境晋级、生产部署、回滚执行和上线窗口协调；
- CloudTrail/ALB/S3 访问日志的长期运维归档策略；
- 7 天试运行值守、试运营运维报告和正式合规认证。

说明：业务告警、业务审计、消息重放、异常队列的软件实现和自动化验证是产品能力，不属于上述运维剥离范围。

### 2.3 明确不属于云端开发的内容

- 设备固件、Android Edge UI/服务、本地数据库和本地离线队列；
- 设备传感器采集、实体控制、安全互锁和设备端命令执行；

- 第三方 ESG 核证和财务级碳核算认证。

| “是否启用”“启用状态”“在线/离线/维护/待机” | 拆成生命周期、业务运行状态、连接状态和 License/Entitlement 四个维度，禁止共用一个字段 |

| “碳排放”图表 | 使用已定义的 ESG 计算口径展示“估算碳减排/CO2e”，显示单位、时间范围、完整率和计算版本 |

## 3. 开发任务执行规范

每个任务必须独立提交，禁止在未声明的情况下扩大范围。开发任务时应遵循：

1. 先读取任务的“依赖”和“技术对接要求”；依赖未满足时不得自行发明契约；
2. 修改代码前先定位现有模块、测试、Schema 和 Migration，保留用户已有改动；
3. 同一任务同时交付实现、自动化测试和必要的契约文档；
4. 所有时间以 UTC 存储；所有 Customer 范围由服务端身份上下文注入；
5. 日志、错误和测试快照不得包含 Token、私钥、密码 Hash 或完整证书包；
6. 状态迁移只能通过领域服务，不允许直接修改状态字段；
7. 验收命令和测试结果必须可重复，不以人工目测代替后端自动化验证；
8. 任务完成后报告变更文件、测试结果、未解决依赖，不报告运维事项。

### 3.1 完成定义

单个任务只有同时满足以下条件才算完成：

- 代码通过 lint、typecheck 和相关单元测试；
- 新增接口已进入 OpenAPI，新增消息已进入 JSON Schema；
- 新增数据库字段具有 Migration 和回滚/兼容说明；
- 鉴权、Customer 隔离、输入校验和错误码均有负向测试；
- 不在日志和响应中泄露未授权数据或敏感密钥材料；
- 任务列出的验收基准全部由测试或确定性检查证明。

本地开发交付与 AWS 目标环境验收分别记录。QA-01～08 的本地 PASS 不能替代真实 AWS 证据；其中依赖真实服务的验收基准统一在 QA-09 集中实跑证明。QA-09 未完成或缺少有效回执时，目标环境保持 `NOT RUN / NO RECEIPT` 或实际失败状态，不得声明整体目标环境验收通过。

# 6. 协议、工程与基础数据任务

## CT-01 建立需求优先级与技术适配登记

- **优先级/类型**：P0 / 契约。
- **依赖**：无。
- **核心开发内容**：在仓库建立版本化决策登记文件；写入 PDF→AWS 方案→`index19.html` 的三级优先原则、Customer 语义、QoS 2→1 适配以及 DEC-001～019；定义每条决策的状态、批准人、版本和影响模块。
- **技术对接要求**：契约包和 OpenAPI 构建必须能引用决策版本；禁止仅写在 README 的非结构化备注。
- **功能边界**：不负责推动业务方做决定，不实现具体功能。
- **交付物**：决策登记、变更模板、契约版本字段。
- **验收基准**：自动检查能识别未决决策；所有已知冲突均有唯一决策 ID；后续 Schema 可追溯到决策版本。

## CT-02 定义 MQTT Topic 与 QoS 契约

- **优先级/类型**：P0 / 契约。
- **依赖**：CT-01、DEC-015。
- **核心开发内容**：定义源稿 8 个上行 Topic 和 3 个下行 Topic 的常量、解析器和发布/订阅权限模板；同时保存 `specifiedQos` 与 `awsEffectiveQos`。DEC-015@1.0.0 选择 ACK 扩展，Catalog 保持 11 个设备 Topic。
- **技术对接要求**：Topic 必须严格为 `bnx/device/{deviceId}/{type}`；ESG Report、Tamper、Command 的规定值 2、AWS 实施值 1；其他 Topic 为 1。
- **功能边界**：不创建 AWS 资源，不处理 Payload。
- **交付物**：Topic catalog、TypeScript 类型、Topic parser、OTA 状态通道路由声明、单元测试。
- **验收基准**：合法 Topic 可解析出 `deviceId/type`；未知层级和空 deviceId 被拒绝；源稿 11 个 Topic 的方向和 QoS 测试全部通过；DEC-015 选定通道只有一个可执行入口。

## CT-03 定义 MQTT JSON Schema

- **优先级/类型**：P0 / 契约。
- **依赖**：CT-01、CT-02、DEC-002、DEC-006、DEC-013、DEC-015、DEC-018。

- **技术对接要求**：证书必须与 Device 匹配；重复 Heartbeat 和重复超时评估均幂等；超时内部状态为 TIMED_OUT，外部映射 REJECTED/ONBOARDING_TIMEOUT，不新增生命周期状态；迟到 Heartbeat 拒绝，重新申请必须使用新 CSR。

- **交付物**：API、状态机、测试。
- **验收基准**：首批超过1台被拒绝；暂停/取消后不得产生新下发；每次状态变化有审计。

## BE-OTA-03 开发 OTA MQTT 下发与状态接收

- **优先级/类型**：P2 / 后端业务。
- **依赖**：BE-OTA-02、CT-02、CT-03、AUTH-04、IAC-01、DEC-015、DEC-016。
- **核心开发内容**：为目标生成 15 分钟一次性下载 grant，发布 OTA Payload/OTA_AVAILABLE，支持 OTA_CANCELLED；按 DEC-015 选定的唯一通道接收设备 ACK 或下载、安装、成功、失败、回滚状态，并按 DEC-016 保存发布/结果记录。
- **技术对接要求**：下行 Payload 含 version、packageType、downloadUrl、sha256、mandatory、scheduledTime；下载经 Device mTLS API 校验 deviceId/targetId/packageId/expiry/unused/revoked 后原子消费；target 下发使用条件 claim + lease，发布前重校验权威状态，状态/history/通知与 publication Outbox 同事务提交；冻结前不得私自新增上行 Topic，使用 ACK 时必须定义 OTA Target 关联键，使用新 Topic 时必须同步 CT-02/03 和 IoT Policy。
- **功能边界**：不实现设备端下载和安装。
- **交付物**：Publisher、状态 Handler、测试。
- **验收基准**：非目标设备不能下载；URL 过期不可用；选定通道的状态迁移和重复上报幂等；不存在第二条未登记回传通道；取消后设备获得正确 Notification。
