# CMP 管理后台前端改进开发计划

状态为待评审。需求来自项目方的《UI Issues of CMP.docx》，共整理出 **44 项反馈**。下表的图号按附件中的截图出现顺序编排。代码基线为 2026-11-18 本地 `main` 的 `97cdd503`。附件反映的是提交反馈时的页面，表中的现况依据该代码基线，实施前仍需在目标环境复现并记录版本。

建议先恢复关键查询、弹窗退出和审批后的列表反馈，再统一筛选区与详情布局。媒体跨页时间排序、配置版本展示和顶部账号身份需要对照 API 和实际数据口径。时区、通知、授权入口、业务设置和重复入口的取舍由项目方定稿，可与首批修复并行评审。

### 技术落点

- **弹窗和详情**。从 `Modal.tsx`、`dialog-a11y.ts` 与 `ConfirmDialog.tsx` 入手。当前通用 Modal 禁用了 Ant Design 内置关闭按钮，Escape 由应用的焦点逻辑处理，各调用页又有不同的退出入口。统一可见的关闭与取消、键盘路径、焦点回收、长内容滚动和请求在途行为。嵌套确认只关闭最上层。校验失败、提交失败和空状态可退出，待确认取消后不发写请求。对耗材和审批沿用后端鉴权、状态、并发和审计校验。
- **筛选和表格**。复用 `ScopeFilter.tsx`、`CursorTable.tsx` 与现有样式。给组合筛选提供单一重置入口，统一字段容器与动作区。筛选草稿、已应用参数和游标同步更新，防止请求迟到覆盖新结果。统一展示密度与完整值查看方式，保留各业务页的筛选语义。
- **身份和概览**。从 `Topbar.tsx` 和 `session-manager.ts` 开始，确认已发布 Cognito ID Token 的可用字段与业务用户的 `displayName` 来源。优先使用已验证的可读名称，再按约定回退至登录名或邮箱。需要补数据时评估最小化的当前用户读取能力。核对 Cognito `sub`、Cognito 用户名与业务 `userId`，以产品确认的标识为准。Dashboard 卡片口径和设备列表跳转对照现有聚合接口。 [总览 API](BE-DASH-01-管理后台总览聚合API.md)
- **配置版本**。当前方案按单设备或型号定向，版本状态接口按版本读取 `CONFIG_CHANGED` Outbox 的目标及投递状态。云端当前生效配置需复用设备 Sync 的解析逻辑，覆盖单设备优先、未来生效、同型号多设备与无匹配版本。按设备展示当前解析结果若需新增查询，先定字段、分页、权限和来源标注。版本列表先做按需展开，有实测数据量压力时再做服务端版本分页。 [配置 API](dev/BE-CFG-01-Configuration版本管理API.md) · [设备 Sync](dev/BE-SYNC-01-Unified-Device-Sync-API.md)
- **媒体排序**。现有 `GET /api/v1/admin/media` 按 ID 升序，游标只带末行 ID。新增可选的采集时间排序方向，推荐客户端默认最新优先，缺省参数沿用旧 API 行为。按 `captureTime` 与 ID 构造稳定组合排序及对应游标，验证正反方向、同一时间的多条记录、筛选切换与旧客户端。按实际查询计划决定是否增加组合索引。先交付后端兼容契约，再启用前端的排序控件。 [媒体契约](../contracts/rest/admin-media-api.json)
- **业务设置**。基线代码中 `alarm.thresholds` 标记为 ACTIVE，由 FE-18 耗材页读取支持的阈值。`command.confirmation` 为 ACTIVE，由 BE-CMD-01 消费。`dictionary.displayNames` 与 `notification.business` 为 STORED_ONLY。实施时按实际代码与接口返回校正文案和设置文档中的历史口径，保留版本校验、审计及只读项行为。 [运行时状态定义](../apps/cloud-api/src/admin/settings/service.ts) · [耗材页接线](../apps/admin-web/src/app/business-controllers.tsx)

## 3. 待项目方确认的行为

| 决策 | 建议及需要确认的内容 |
| --- | --- |
| D1 通知铃铛 | 建议当前先隐藏无交互入口。若需保留，明确是直接进入现有告警页，还是建设独立通知中心。独立通知中心需明确消息来源、可见范围、已读状态和未读计数。 |
| D2 时区选项 | 建议保留上海和 UTC，伦敦和纽约按实际运营地区决定。确认显示偏好与业务日历的范围，延续 UTC 存储及登录默认上海。 |
| D3 授权管理入口 | 建议先保留独立入口，由运营确认跨合约和跨设备操作是否有替代路径。合约负责商业租期与设备关联，License 负责设备能力授权，菜单取舍沿用现有业务分工。 [合约与授权关系](dev/DEC-007-Contract与License关系.md) |
| D4 业务设置入口 | 建议保留给现有获授权的管理员并展示消费方及状态。项目方确认常用设置、可编辑范围，以及仅存储项是否继续展示。 |
| D5 配置版本 | 确认运营需要看“云端当前生效版本”“设备最后实际应用版本”还是两者。后者先查已有回执契约及持久化字段，缺失时再评估设备方联调和数据补齐。 |
| D6 设备用户主入口 | 建议以 `/device-users` 为主入口，用户管理页保留跳转或移除重复页签。确认旧入口的兼容策略，用五种角色校验原可访问者和只读用户的访问路径。 |

CMP-02 默认沿用现有取数口径，项目方若希望优先展示在线、最近活跃或指定设备，先确定排序、过滤和并列项规则，再改聚合契约。CMP-16 默认使用页面显示时区输入并换算成 UTC，评审时可确认是否更适合固定 UTC 输入。

## 4. 验证与交付

1. **定向自动化**。运行 `pnpm --filter @fdp/admin-web typecheck`、`pnpm exec vitest run apps/admin-web/test` 和 `pnpm check:admin-web-e2e`。补足本轮故障的具体回归用例。涉及媒体或配置 API 时增加对应服务和契约验证，并运行 `pnpm openapi:check`。
2. **交互与视觉**。至少覆盖 1366×768、1440×900 以及窄视口，中英双语、长名称、空状态、失败重试与键盘操作。重点核对查询重置、分页、弹窗及详情的焦点、高风险确认和重复提交。沿用现有浏览器回归入口。 [后台 E2E](dev/QA-05-管理后台E2E测试.md) · [原型与视觉回归](dev/QA-08-客户原型追踪与视觉行为回归测试.md)
3. **目标环境**。在实际测试环境绑定前端构建和 API 版本，以平台管理员、设备操作员、审计员、客户管理员和客户只读用户做代表性验收。按角色核对菜单可见性、租户范围、写权限和脱敏。在媒体跨页排序、配置状态与耗材申请等链路使用受控数据，保留查询、保存后读回或权限拒绝的证据。
4. **项目方签收**。以 CMP 编号回填验收结果和证据链接。未取得决策或数据的项记为 `OPEN` 或 `BLOCKED`，实际环境未执行的用例记为 `NOT_RUN`。分批发布时记录相应前端构建与 API 版本，回归失败时按批回退到上一兼容版本。
