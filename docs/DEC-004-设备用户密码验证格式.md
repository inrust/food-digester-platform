# DEC-004 Device User 密码验证格式

DEC-004 是协议冻结门禁决策（当前 `pending`，登记版本 `0.2.0`）。按《管理后台开发任务清单》§4 末段，本任务把暂定值落地为数据驱动、可整体替换的策略扩展点。**决策本身未冻结，冻结必须经业务方批准人按 [decision-change-template.md](../contracts/decisions/decision-change-template.md) 执行。**

## 暂定值（provisional）

> 设备本地专用加盐验证值，禁止复用云端密码 Hash。

| 策略面 | 暂定结论 | 消费任务 |
|---|---|---|
| 分离 | 验证值仅供设备本地登录校验；禁止复用 Cognito/云端密码 Hash；不赋予云端登录权限 | BE-DUSR-02 |
| 材料结构 | 固定四字段 `version`+`kdf`+`salt`+`hash`；`version` 支持算法迁移；每用户独立随机 salt | BE-DUSR-02 |
| 下发 | 仅经 Unified Device Sync 的 Device Users 域下发；查询类 API 不得返回；日志/审计脱敏 | BE-DUSR-02、BE-SYNC-01 |

## 待冻结参数（fail-closed）

DEC-004 的核心未定项是 **KDF 具体格式**，本策略以 `null` 显式标记，读取即抛 `PolicyParameterPendingError`：

- `material.kdf`：KDF 算法标识；
- `material.kdfParameters`：KDF 参数（迭代次数/内存等）；
- `material.saltBytes` / `material.hashBytes`：salt 与 hash 长度（下限约束 salt≥8、hash≥16 字节已由 Schema 锁定）。

冻结时必须同时提供固定测试向量供设备方复验（BE-DUSR-02 验收基准）。

## 使用约束

1. BE-DUSR-02 只能经 `device-user-verifier-policy.ts` 查询，禁止直接读 JSON 或复制暂定值；
2. 冻结前不得实现具体 KDF 计算（参数不可得即失败关闭）；可先实现 KDF adapter 接口、DTO 结构与脱敏管线；
3. `status: provisional` 期间，数据库字段按"字符串验证值 + 版本"设计，不得把具体算法固化为列结构。

## 冻结升级路径

1. 业务方批准 DEC-004（登记升至 `>= 1.0.0`、`frozen`）；
2. 填入 KDF 算法/参数/长度，`status` 改 `frozen`，提升 `policyVersion` 并同步 `x-decision-versions`；
3. 在 BE-DUSR-02 中补充固定测试向量测试。
