## 独立资源与权限

| 阶段 | 声明资源                                                                  | 限制                                                                    |
| ---- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| A    | Writer 函数、角色、专用边界、日志组、数字 Version、异步设置，共6项        | 无 CONTROL PutItem，不发布未绑定 Verifier                               |
| B    | 在 A 上增加相同6类 Verifier 资源，共12项；Writer 仅调整角色 inline policy | 单个实际 DEVICE#UUID PutItem；Writer 代码、manifest 和 Version 资源不变 |

网络只导入现有两个私有子网及一个已核验的执行 SG；不创建 VPC/SG/入站规则/NAT/DB/Secret/表/公开入口/事件触发器。Verifier 无 VPC、DB、DynamoDB、Cognito。两个函数并发各1、30秒 timeout、Writer pool1；runtime FunctionUpdate 并在发布后记录具体 RuntimeVersionArn。日志30天保留，所有资源 Retain 供审计；Retain 不等于自动停用，清理必须由受控步骤完成。

EventInvokeConfig 不是触发器：它显式设置已发布版本 MaximumRetryAttempts=0、MaximumEventAge=60秒，无成功/失败转发目的地。避免把 AWS 缺省异步重试误当作已关闭。调用协调器应使用同步 RequestResponse；本批不包含真实 Invoke 操作。

运行策略仍允许 CONTROL 全表 GetItem 元数据，Put 仅为绑定设备，不授予 PAYLOAD、DeleteItem、UpdateItem、Scan。ENI 六动作的 Resource=* 是服务例外，搭配 SourceFunctionArn Deny 限制函数代码直接调 EC2。边界是权限上限；A 的 inline 不含 Put 即不获写授权。

B 必须提供精确 Writer manifest 的成功 BIND_DEVICE 收据、安全来源引用、operation/request Hash、不可变设备/客户/站点/证书，以及 A 的 Writer ZIP SHA。任一 UUID、两 manifest 关联或原 ZIP 漂移，拒绝合成。收据必须来自后续受控 READ_OPERATION/可信采集，本地 JSON 结构通过不证明目标收据真实。

控制面需要新增两角色 /img21/ 路径及两专用边界的精确管理/PassRole 范围。policies.ts 生成增量，local-synth 只输出 review-only 提案并保留原文件 Hash；**未修改** infra/iam/FDP-DeploymentBoundary.json 和 FDP-CloudFormationExecutionPolicy.json。原根路径 Deny 及 Service/Migration 边界不变，新路径各自有明确错误边界 Deny。真实 apply/effective permissions/SCP 仍需单独审核，不将本地策略断言当 AWS IAM 模拟。

连接预算要求所有19个既有数据库函数的实际并发/pool、原生普通连接数、其他客户端占用及最新来源，保留 operational>=8、idle overlap>=10 后才能增加 Writer 一条连接。夹具为普通70、既有46、保留18、Writer1、余5；这是源配置演练，**未证明目标有5条余量**。网络/预算证据本地结构要求最多5分钟新鲜；真实 SG 5432/出站443、路由/Secret 可达性、账户并发余量另需目标核验。

## 两份 manifest 与数字版本

不能把 Lambda 未发布的数字编号写进 ZIP 再猜它一定成为该编号。MC02 renderer 使用明确的 PUBLISHED 模式：

1. 冻结 Writer canonical manifest、工具/应用源标识和 ZIP，持久账本以后只认该 Hash。角色阶段 B 不修改这些字节。
2. CfnVersion 在 Function 创建/更新后发布，以 ZIP CodeSha256 限制代码；输出真实数字版本 ARN。不创建 alias/Function URL，不附加 operator Invoke grant。
3. 在获批的目标阶段，使用 createReadOnlyPublicationObserver 读取实际数字版本。它仅执行固定只读 CLI：STS identity，Lambda function/concurrency/runtime/event-invoke/policy（基函数与数字版本），IAM role/inline/attached/boundary 版本。13次读取，依赖项顺序读取、其他并行；本批测试全部用注入端口，没有运行真实 CLI。
4. prepareInvokePolicy 用采集**前**的时间及 I/O 后的新时钟复核：完整采集最多15秒新鲜，账号、数字 ARN/Version、ZIP SHA、环境 Hash、Role、架构/timeout/memory/handler/状态、网络、具体 runtime、trust/inline/boundary及额外挂载/Layer等均匹配。不允许额外 managed policy、resource-based invoke policy 或异步重试/转发。
5. 通过后只生成 unapplied Invoke JSON：Writer 仅固定实际数字版本且到准备窗口结束；Verifier 单独固定数字版本且最迟到快照 expiry。不能把两者共用五分钟截止而阻断 Writer 清理。执行者不得修改源码、配置、role/boundary 或 PassRole；部署身份与调用身份分离。
6. 调用前重新读取可变 role/runtime/config；15秒 ticket 不是90分钟内的持续不变证明。IAM 冻结/有效权限验证、真正授权应用与调用、窗口确认均仍待目标执行。生成 JSON 本身不授权任何人。

旧固定数字模式保持原精确相等检查。PUBLISHED 模式仍要求 Lambda 受信 context 中 functionVersion 是正整数，invokedFunctionArn 必须明确为相同数字，$LATEST/alias/base ARN 均拒绝。数字选择绑定发生在 Code/manifest 不再变化的发布后；IAM精确 ARN 和协调器验证共同收口。应用的 cloudAdmission strict 规则及旧部署 SHA 判定未改，不把这套工具发布证据当作 MC03 已完成。

观察器不会持久化 GetFunction 的签名下载 URL、Description 或环境明文，只保留环境 Hash和所需公开配置。旧策略或默认 CLI 权限是否覆盖新增只读动作尚未验证；不足则 BLOCKED，不自增权限。

## Verifier 五分钟期限

取得真实当前 Sync 快照后，受信采集提供 observedAt、SourceRef、完整不可变设备绑定、licenseId/version、snapshotEtag。源引用不是签名证明：真实快照来源/身份和采集时间须由后续可信链路提供，不能手填新时间重用旧文件。

renderVerifierManifest 只从原 Writer 派生独立 manifest；expiresAt=min(observedAt+300秒, 窗口结束)。打包、排队、上传、CloudFormation 发布耗时都消耗同一预算，禁止以渲染/发布完成时刻重置。验证阶段拒绝未来采集、过期、跨租户/设备/证书/版本/ETag、错 key 版本；取 key 前、异步后、返回前均检查。发布期间超时则不生成 Invoke JSON；重新取当前快照、重新打包/发布 Verifier 并替换其旧 grant，Writer manifest/root/Version 不动。

manifest-pair.json 记录两 Hash、原始 snapshot proof Hash、SourceRef、观察时间和截止。两份配置只能通过同一 run/candidate/设备归属关联，不能复制 Writer Hash 给 Verifier。Nonce 仍只关联一次请求/响应，不宣称全局防重放账本。

## 实施顺序和回退

当前仅执行本地阶段：类型/测试 → bundle/ZIP实体核验 → A/B synth → 策略/资源差异 → 可复算证据。下一步 MC03 冻结当前候选和工具清单，刷新 G3/发布绑定证据，保持默认 strict；完成后才提交精确目标写范围与新窗口申请。

获批后按 A 部署/发布观察 → 单独审阅 Writer Invoke → 正常创建与首次登录身份、设备业务流程 → 读取 BIND_DEVICE 收据 → 采集当前 License 快照并生成 B → 审阅并另批 B 单 UUID 策略及目标更新范围 → B 发布并新观察 → 审阅 Verifier Invoke → 正常 License VERIFIED/Active → 唯一设备预览准备。真实 G4 CF01/02/03 仍另批执行，不等待 App/真机。

回退先停止新调用并查询 UNKNOWN 操作；保留阶段 B 关闭能力，使用当前 epoch 关闭白名单/流，按顺序停用本轮身份，确认无外部租约。再撤 Verifier Invoke/Writer Invoke、将工具并发置0、移回 A 权限并保留版本/日志/审计。不要先撤 Put/Invoke 使清理入口失效，也不依靠 stack rollback、租约过期或 Retain 自动撤白名单。到期未清理需记录 BLOCKED 并获取恢复窗口，不复用旧准备授权，不直接改 PG 账本或生命周期。无法确定结果保持 query-only。
